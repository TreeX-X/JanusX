# Agent Note: 设置界面与外部终端及多 CLI 待办

## Problem

设置界面的唤出与退出缺少过渡，视觉上是硬切，窗口层级与焦点归位也未经打磨。Office CLI 是否保留在设置界面中尚未定论，继续占位会稀释设置信息层级，贸然移除又可能打断既有入口。外部终端交互仍显粗糙，输出回流、状态反馈与错误自愈尚未对齐内部终端体验。LLM 多 CLI 管理配置只覆盖了检测与安装陈列，画像切换、凭据落盘与回滚验证仍是断点。若长期搁置，设置与终端两条线的体验债会叠加，后续改动只能在不一致的地基上打补丁。

## Proposal

分四路推进，全部落在设置与终端现有契约上，不另起新面孔。设置唤出退出将补齐进入与退出过渡，统一时长与缓动，退出时把焦点还给唤出源，遮罩点击与 Esc 走同一条关闭路径。Office CLI 去留先做一次信息架构分析，结论只有保留并收敛层级或移出设置两种，分析通过后再动手。外部终端交互沿用内部终端的反馈语言，补齐执行中状态、失败尾部输出与可操作的下一步。LLM 多 CLI 管理补齐画像存取、按应用投影写回、原子写加备份与激活后重读校验，形成检测到切换的完整闭环。

## Alternatives considered

- 设置过渡直接复用现有全局动画 — 最强理由是不新增动效体系，上线最快。不可取的原因是设置是模态层，焦点管理与层级语义和普通视图不同，硬套全局动画盖不住硬切感。
- Office CLI 直接移出设置不做分析 — 最强理由是页面立刻清爽。不可取的原因是入口迁移涉及既有用户路径，没有使用依据的移除只是把问题推给出入口。
- 外部终端交互与内部终端彻底同构 — 最强理由是体验完全一致。不可取的原因是外部进程生命周期不受控，强同构会引入大量异常分支，得不偿失，只对齐反馈语言即可。
- Do nothing / reuse — 维持现状零成本，现有检测与安装面板继续可用。代价是四处体验债并存，设置硬切、入口含混、外部终端粗糙、多 CLI 断点会互相放大。

## Acceptance criteria

- [ ] 设置界面唤出与退出具备一致的过渡效果，Esc、遮罩点击与关闭按钮走同一关闭路径并归还焦点。
- [ ] 输出 Office CLI 去留分析结论，明确保留收敛或移出二选一，并给出入口迁移方案。
- [ ] 外部终端具备执行中状态、可读的失败输出与下一步操作，交互语言与内部终端一致。
- [ ] LLM 多 CLI 管理跑通检测、画像切换、写回、备份与重读校验，二次激活可观察到前一次写入。

## Risks

- 动效打磨容易滑向过度设计。缓解：时长与缓动只收敛到一套令牌，不做逐页特效。
- Office CLI 分析无数据支撑会变成主观取舍。缓解：先列入口点击与配置使用事实，再下结论。

## Landing status (2026-09-18 reconcile, commit-evidence only)

- 设置过渡动效：已落地（`8db92ff`，与蓝图工作台过渡对齐）。
- LLM 多 CLI 闭环（检测/画像/写回/备份/重读校验）：部分落地——检测与安装陈列、bindings、Anthropic 类型、Claude 写回加备份与重读校验（`2a701aa`、`4b4eb65`）、per-terminal projectors（`59752d4`）、provider collections（`5e70d50`）；二次激活可观察性与 Codex/OpenCode/Pi 的 live 写回验收仍待补。
- 未动：Office CLI 去留分析（无结论输出）；外部终端交互对齐（无提交证据）。
- 外部终端环境差异大，统一反馈可能掩盖真实错误。缓解：失败时保留原始尾部输出原文，只做裁剪不做改写。
