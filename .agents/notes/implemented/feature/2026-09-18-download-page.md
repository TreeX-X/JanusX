# Agent Note: JanusX download page

Status: implemented

## Problem

Visitors need to choose a Windows package and understand installation before exploring the application. Repeated download actions separated by feature cards obscure that task. A failed release request is also insufficient evidence that the first release is still being prepared.

## Decision

The public page uses a centered introduction with an immediate Windows installer action, a brand visual, a two-column package section, installation steps, and support links. The package section retains the shared alignment, restrained separators and clear package labels inspired by [Orca's download page](https://www.onorca.dev/download). The introduction and expanding visual take their interaction direction from [MiMo](https://mimo.mi.com/), using JanusX's existing icon, neutral shell surfaces, system typography and orange accent. Small screens stack the package options and steps.

The brand visual has one silver particle capsule with two eyes, a plain JanusX wordmark and a neutral black background. On larger screens the particles converge once in about 1.8 seconds and respond locally to the mouse. A short sticky scroll stage expands the card to the viewport width and blends into the six-pane workspace: Claude, Codex, OpenCode and Pi terminals alongside native CPA and Markdown preview. The stage reserves the final card height plus 60% of the viewport height for the transition; scrolling back reverses the transition without replaying the entrance. Small screens, short viewports, reduced-motion preferences and unavailable Canvas/JavaScript show the scene followed by the workspace without reserved scroll space. Canvas work stops once the particles settle and pauses outside the viewport or in hidden tabs. The first-screen download action shares the package section's validated installer URL, missing-package state and release-history fallback.

Four buttons select the overview, terminals, CPA or document capture. Selection updates the image, alternative text, description, pressed state and original-image links only after decoding succeeds. Failure preserves the previous view and permits retry; the last requested selection wins. Images open at full size for readable details. Without JavaScript the overview and its link remain accessible. Mobile and reduced-motion visitors have the same view controls without the sticky animation.

The site remains static on gh-pages. Release lookup selects only explicitly named JanusX Windows x64 assets, checks their GitHub download origin, and shows actual package sizes and publication date. Missing packages link to release history. An HTTP 404 means no public stable release is found; network errors, timeouts, and rate limits display a separate unavailable state. Without JavaScript the release links remain usable.

## Alternatives considered

Reusing the existing feature-led page avoids layout maintenance, but leaves the primary download decision spread across two sections. Copying Orca's entire platform matrix offers consistent platform browsing, but advertises packages JanusX does not publicly provide. A framework-based site supports future routing but adds a build and dependency pipeline to a single static download page.

## Consequences

The page makes the primary installer available before the visual, followed by detailed package selection, installation steps and six current black-theme feature captures: four terminals, CPA, Markdown editing/preview, files/code, session history and external sessions. These replace the older GIF presentations of the sidebar, standalone Janus CLI, roundtable, blueprint and knowledge tools. This iteration demonstrates real interface states rather than operation playback; no page asset uses the old recordings. The copy states that CLIs require installation and their own login or model configuration for model tasks.

The four hero views were captured on 2026-10-19 by `scripts/capture-workspace.mjs`, using the sibling app checkout's clean CLI fixture and real Electron build at `.cache/readme-blueprint-build/main/index.js`. The app shell and CPA's own appearance control both use dark. Native CPA capture uses the attached WebContentsView bounds, rather than an empty renderer screenshot. Installed immutable CPA components are hash-verified; backend v8.0.32 and frontend v1.26.5 run in a new local instance with zero accounts/requests. No real account configuration is copied. Terminal text is unsent task drafts; the document is authored demonstration content. Four project panes and two tool panes are asserted before the overview capture, and Retry/error states are rejected. Keep the default 62% project width: narrowing two terminal columns too far caused OpenCode/Bun to crash during capture. Do not disguise that failure with edited screenshots.

`assets/workspace/capture.json` records the new asset hashes, dimensions, pane counts, CPA versions and app entry hash. Captures are staged until all four succeed. `imported.json` records the original raw PNG sources/hashes for three recent dark app recordings: tools/filetree, session detail and external-session transcript. The latter two use authored demonstration conversations; no model result or successful Resume is claimed. Source documentation is the app repository's [README showcase Note](https://github.com/TreeX-X/JanusX/blob/main/.agents/notes/desktop/readme-showcase.md). The historical product-tour Note link no longer resolves and is superseded here. These recordings use an existing build with unpinned dirty source provenance, not a claim of reproducibility from HEAD or a specific public release.

Re-capture from the app checkout with `JANUSX_APP_ROOT` set to that checkout, `SHOWCASE_ENTRY` set to its prepared Electron entry, `SHOWCASE_GIFTOOLS` pointing at temporary pngjs/gifenc dependencies, and `SHOWCASE_CPA_COMPONENTS` pointing at the installed component directory; run `node ../JanusX-gh-pages/scripts/capture-workspace.mjs`. This does not change the app's shared recording theme or the user's current session. Branch-local PNGs keep the page independent of app-branch asset URLs. All images declare dimensions and descriptive alternative text; feature images load lazily. The former `tour.js` playback script is removed because the page no longer embeds GIFs.

CSS and release handling are separate files to keep layout and failure behavior inspectable. Package filenames must retain the builder's explicit x64 naming; additional architectures require explicit choices rather than silently changing the selected binary. GitHub API availability affects live metadata, while release-history links provide the fallback.

Run `node tests/download.test.cjs` with Playwright available through `JANUSX_PLAYWRIGHT` or the normal module lookup. The check verifies the seven PNG hashes and six-pane/native-view evidence, release success, missing packages, wrong architectures, empty releases, request failures, invalid URLs, no JavaScript, all six updated feature images and five viewport bounds. Screenshots are written outside the site when `JANUSX_SCREENSHOTS` is set.

Run `node tests/hero.test.cjs` with the same Playwright configuration to verify first-screen installer routing and failure fallback, particle settling and pointer response, expansion/reversal, all four view controls, failed-image preservation, mobile controls, live reduced-motion changes and accessible no-JavaScript fallback. With `JANUSX_SCREENSHOTS` set, it captures desktop, expanded, individual feature, mobile and reduced-motion views. Both suites passed on 2026-10-19; preview captures were visually inspected at `%TEMP%/janusx-black-preview`. Keep generated screenshots outside the published site.
