# Agent Note: Conventional file glyph for the drawer's Markdown view

Status: implemented

## Problem

The bottom drawer in `TerminalArea.tsx` switches between the runtime telemetry view and the Markdown note view with two tabs pinned to the right of the drawer header. The runtime tab carries lucide's `Activity`, a single four-segment polyline with no container, while the note tab carries `NotebookPen`, which draws six separate shapes: a page with an open corner, four binding ticks down its left edge, and a diagonal pen crossing the whole glyph. `TabStrip.module.css` renders the tab icons at 12px, and at that size the four ticks — spaced four units apart on lucide's 24-grid, so two pixels apart once scaled — merge into a solid smudge along the page's left edge, while the pen adds a sixth direction of movement to a glyph already carrying five. The two tabs therefore have wildly different optical weights sitting side by side in the same 28px header.

The same `NotebookPen` is reused as the note pane's empty-state mark in `QuickNote.tsx`, rendered at 22px on a 22px box with `strokeWidth` 1.5 and the color `rgba(255,255,255,0.18)`. There the ticks and the pen read as noise rather than meaning, and the glyph's mass comes mostly from the page outline rather than from anything that says "Markdown".

## Decision

`components/ui/MarkdownIcon.tsx` is a new glyph that keeps the conventional file shape and puts the markdown mark where a text file's lines would sit. It draws four paths on lucide's 24-grid with the same round caps and joins: the page with its folded corner (`M15 2H6a2 2 0 0 0-2 2v16a2 2 0 0 0 2 2h12a2 2 0 0 0 2-2V7Z` plus the fold `M14 2v4a2 2 0 0 0 2 2h4`), then the markdown mark `M5 18v-7l3.5 3.5L12 11v7` and the down chevron `M16.5 11v6m-1.75-2.25 1.75 2.25 1.75-2.25`. The fold is the part that makes the shape read as a file rather than a box, so it stays; the binding ticks and the pen are what made the glyph busy, so they go. The mark is placed in the page's lower two-thirds at `y` 11 to 18, which is where `FileText` puts its own text lines, so the glyph keeps the conventional file's proportions and simply carries markdown content instead of generic lines.

Two earlier candidates were built and rejected in review. A bare markdown mark with no page at all — just the `M` and the chevron — is the lightest possible reading and matches `Activity`'s container-free style, but the user judged it too minimal: five line segments floating in a 28px header read as a stray glyph rather than a view. Dropping the fold and keeping only a rounded rectangle was rejected for the opposite reason, because without the corner the shape stops reading as a file. The conventional page plus the markdown mark inside is the version that satisfies both constraints the user stated: it should look like a normal file icon, and it should still represent Markdown.

`MarkdownIcon` exposes `className`, `strokeWidth` and `aria-hidden`, matching the props the two call sites already pass to a lucide icon, and takes `strokeWidth` as `number | string` so it can sit in the same record as `Activity`. `DrawerViewTabs` in `quick-note-behavior.ts` types `DRAWER_VIEW_ICONS` as `Record<DrawerView, ComponentType<MarkdownIconProps>>` and maps the note view to it; the runtime view keeps `Activity`. The tab strip's own color rules still apply, because the glyph inherits `currentColor` and takes `--shell-dim` at rest and `--shell-accent` when selected, exactly as the lucide icons did. `QuickNote.tsx` renders the same glyph in its empty state at `strokeWidth` 1.4.

The empty-state box moves from 22px to 24px and its color from `rgba(255,255,255,0.18)` to `rgba(255,255,255,0.22)`. The new glyph has less mass than `NotebookPen` — no ticks, no pen — so the original tuning left it nearly invisible on the black tray; one step of size and one step of opacity restores the balance without making the decorative mark compete with the empty-state text on `--shell-dim`.

## Alternatives considered

- Keep `NotebookPen` — strongest case is that it is a stock lucide icon with no maintenance cost and it does name a notebook. The driver that rules it out is the user's own reading of the shipped result: at 12px the ticks and the pen turn the tab into smudge, which is the specific defect the change was asked to remove.
- A bare markdown mark with no page — strongest case is that it is the lightest glyph possible, matches `Activity`'s container-free style, and needs only two paths. The driver that rules it out is the user's verdict on the live build: too minimal, and it stops reading as a file.
- Lucide's `FileText` — strongest case is that it is the conventional file icon with zero new code. The driver that rules it out is that its three generic text lines say nothing about Markdown, and the user asked for a glyph that still represents the format.
- A rounded rectangle with the markdown mark inside and no fold — strongest case is that it drops to three shapes and gives the mark more room. The driver that rules it out is that the folded corner is what makes the shape read as a file rather than a box, which is the property the user asked to keep.
- Reuse `FileTypeIcon`'s markdown glyph from the file tree — strongest case is that it is the same "page plus mark" idea the user already sees on every `.md` row, so the drawer tab would match the tree. The driver that rules it out is that `FileTypeIcon` bakes in a `colorToken` class that paints the glyph with the file-kind color, which would break the tab strip's dim-to-accent treatment, and it is drawn on a 16-grid that scales the interior mark down to roughly 4.6px at the tab's 12px.

## Consequences

- **Gains**: The Markdown tab drops from six shapes to four and its optical weight now sits close to the runtime tab beside it, so the two view switches read as one control instead of two different kinds of mark. The glyph keeps a conventional file silhouette while still naming Markdown through the `M` and the down chevron. The empty-state mark loses the ticks and the pen and gains one step of size and opacity, so it reads as a quiet watermark rather than a smudge. No color rule changed: the glyph inherits `currentColor` and the existing tab strip and empty-state treatments still govern it.
- **Costs and limits**: `MarkdownIcon` is a hand-rolled glyph rather than a stock icon, so it will not follow a lucide upgrade the way the other tab icon does; the same is already true of `WorkbenchIcon` and `FileTypeIcon` in this codebase. The mark sits at `y` 11 to 18 inside the page, which leaves the glyph's top third empty apart from the fold, so at 12px the interior mark is about 3px wide and the glyph leans on the page outline to carry its size. The 24-grid geometry was chosen for the drawer tab; if a future call site needs the glyph below 12px the interior mark should be enlarged or dropped rather than the whole glyph scaled. `DrawerViewTabs` now depends on `ComponentType` from React for the shared record type, which is the only reason the icon's `strokeWidth` prop is widened to `number | string`. The empty-state size and opacity are hand-tuned constants with no measurement behind them, matching how the rest of `QuickNote.module.css` sets its 24px icon buttons.
- **Verification**: `npm run typecheck` passes, including the `ComponentType<MarkdownIconProps>` record that holds `Activity` and `MarkdownIcon` together. `npx eslint` on `MarkdownIcon.tsx`, `QuickNote.tsx`, `quick-note-behavior.ts` and the note directory reports nothing. `npx vitest run tests/unit/note` passes 49 tests, with `quick-note-view.test.ts` still asserting that the drawer tabs render an `<svg` and keep their tab and panel associations. `npm run test:unit -- --run` passes 251 files and 1796 tests; `tests/unit/task-contract-adoption.test.ts` failed on two of four full-suite runs by exceeding its own 5000ms command timeout on a `git clone --no-local` step under load, and passes both in isolation and in the other two runs, so it is unrelated flake in a main-process test that touches none of the files changed here. The visual result was reviewed by the user in the running app, who rejected the earlier bare-mark glyph as too minimal and asked for the conventional file design, which is the version recorded here.
