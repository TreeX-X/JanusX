# Agent Note: Note drawer segmented tabs and Markdown toolbar

Status: implemented

## Problem

The bottom drawer in `TerminalArea.tsx` switches between the runtime telemetry view and the note view with two filled chips: the active chip is an accent-tinted block and the idle chip a near-black block, so the switch reads as a status badge instead of a control and breaks with the neutral, raised selection state that the settings navigation and the right dock tabs share. The note pane paints its container, its editor and its buttons with hand-picked near-black values (`#0d0f10`, `#0a0c0d`, `#17191b`) inside a drawer whose chrome sits at `#1e1e20`, which punches a black hole into the surface ramp that `globals.css` reserves pure black for shadows only. The editor itself is a bare textarea behind an Edit/Preview toggle: no formatting affordances, no shortcuts, no list continuation, so every Markdown marker is typed by hand, and the toggle throws away the side-by-side reading that a drawer this wide can afford.

## Decision

`SegmentedControl.module.css` under `components/ui` holds one segmented control for both switches: a 1px container on the shared control border, segments that are transparent at rest, and a selected segment that steps up to `--shell-active` with a 1px drop shadow while only its icon takes the accent. The accent never fills a segment, because a tinted block in this shell means a warning or a selection bar, not a mode. `DrawerViewTabs` in `quick-note-behavior.ts` renders that control with an activity icon for the runtime view and a notebook icon for the note view; the caller passes localized labels (`terminal:tab.view.runtime` reads 上下文监控 / Context, `terminal:tab.view.note` reads Markdown) and the view id remains the fallback label, so the tabs render without an i18n provider in unit tests. The tab list stops click propagation itself so a click on its padding never toggles the drawer, and `TerminalArea.tsx` reserves `pr-52` in the drawer header for it.

The note pane shares the panel treatment of the runtime view in the same drawer: a 1px `--shell-border` frame and a 1.2% white lift over the drawer chrome, so switching tabs never changes the panel's depth and no surface inside the drawer drops below the chrome. Dividers are hairlines on `--shell-border-soft`, the editor and the preview are transparent, and the active card in the list carries the same 2px left accent bar and `--shell-active` fill as the settings navigation. The list shows a stripped first-line excerpt and the update age per card, and it folds away when a `ResizeObserver` measures the pane under 520px, because below that width the list would leave the editor narrower than its toolbar.

Editing has three modes in a second segmented group: edit, split and preview. Split renders the textarea and the preview side by side; preview alone hides the toolbar. The preview keeps `MARKDOWN_COMPONENTS` and the `markdown-preview` class, whose ownership stays with [markdown preview local assets](../bug-fix/2026-09-18-markdown-preview-local-assets.md). The toolbar offers fifteen actions in four groups: heading levels one to three; bold, italic, strikethrough and inline code; bullet, numbered and task lists plus quote; link, fenced code block, table and divider. Bold, italic, inline code and link answer to Mod+B, Mod+I, Mod+E and Mod+K, strikethrough to Mod+Shift+X; every button title carries its shortcut in the platform's notation. Enter inside a list item continues the list with the next marker or ordinal and Enter on an empty item leaves the list; Tab and Shift+Tab indent and outdent the caret line or the selected lines by two spaces. The footer shows a word and character count, where each CJK character counts as one word, next to the export menu and the paste button.

`quick-note-format.ts` owns the editing rules as pure functions and never touches the DOM: each action resolves to a `NoteEdit`, which is the replaced range, the replacement text and the selection the editor must end with. Inline marks wrap the selection, or the word around a collapsed caret, and remove the markers when the selection or its surroundings already carry them. Line marks apply to every non-blank line in the selection and remove themselves when every such line already carries the mark; a heading action replaces an existing level instead of stacking hashes, and a list action converts between list kinds. Blocks always land between blank lines, because a `---` glued to the previous line turns that line into a setext heading and a table swallows every following non-blank line as a row. `QuickNote.tsx` applies an edit by selecting the range and calling `document.execCommand` with `insertText`, or `delete` when the replacement is empty, so the change enters the textarea's native undo stack and Ctrl+Z reverts one toolbar action at a time; when `execCommand` is unavailable or the resulting value differs from the expected one, the pane writes the value to the note store and restores the selection in a layout effect after React commits the controlled value. Without the execCommand path, every toolbar action would clear the browser's undo history for the field.

## Alternatives considered

- Mount Monaco for the note editor — strongest case is that `FileEditor` already ships Monaco with undo, find and multi-cursor, and a Markdown language mode exists. The driver that rules it out is the boot cost and worker set-up for a scratch pad inside a 380px drawer, plus Monaco's own keybinding and theme surface that the toolbar would have to bridge; a textarea with execCommand keeps native undo and IME composition for free.
- A contenteditable rich-text editor that hides the markers — strongest case is that the writer never sees `**` or `#`. The driver that rules it out is that the note's payload is pasted into terminals and exported as Markdown text, so the source is the product and must stay visible and exact.
- Keep the two chips and recolor them neutral — strongest case is the smallest diff. The driver that rules it out is that the chip-per-view shape stays a pair of blocks, and the mode switch inside the pane needs the same control, so one shared segmented module pays for itself twice and matches the raised-neutral selection the dock and the settings already use.
- Do nothing / reuse — keeps the black pane, the filled chips and the bare textarea. The cost is the visual break with the surface ramp and the manual markup on every line, which is what the drawer's note view exists to remove.

## Consequences

- **Gains**: The drawer switch and the mode switch read as controls of the same family as the rest of the shell, and the note pane sits inside the surface ramp instead of below it. Markdown writing gets a toolbar, shortcuts, list continuation and indentation, and a split view for reading while writing; each toolbar action is one undo step.
- **Costs and limits**: `document.execCommand` is deprecated in the web platform though supported by Chromium and therefore Electron; when it returns false the fallback path still applies the edit but the browser's undo stack does not include it. Toolbar actions read the raw textarea selection, so in split mode they act on the left pane only and the preview stays read-only. The editing mode lives in component state and resets to edit whenever the drawer remounts the pane. The 520px compact threshold is a constant, not derived from the toolbar's measured width. Shortcuts are intercepted only while the textarea has focus, and an Electron menu accelerator on the same key would win if one is added. The textarea captures Tab and Shift+Tab for indentation, so keyboard focus leaves the editor through the mouse or the shell's own focus shortcuts, never through Tab order. The word count treats each CJK character as a word, which overstates counts for long compounds. The drawer heights, the drag handle and the runtime cards stay owned by [runtime drawer cards and drag height](./2026-09-19-runtime-drawer-cards-resize.md).
- **Verification**: `npx vitest run tests/unit/note` passes 49 tests, including `quick-note-format.test.ts` for the splice rules and `quick-note-view.test.ts` for the segmented tab markup, the header reservation and the export menu. A Vite and Playwright harness rendering `QuickNote` with `DrawerViewTabs` at 1180px and 640px confirms in Chromium that bold via the toolbar wraps the selection and keeps it selected, Ctrl+Z reverts it, Enter after a task item inserts `- [ ] `, Ctrl+K inserts a link, and the computed backgrounds are `rgb(30, 30, 32)` for the drawer and a translucent white lift for the pane with no pure black surface.
