# Android 扫码配对与真实远程终端

## Expected behavior

电脑在设置的创新功能中开启远程协作控制后，才显示远程入口并允许启动服务。远程默认选择当前工作区，也允许在开启前明确选择其他已登记工作区。电脑生成临时二维码，Android App 扫码后申请配对，经电脑拥有者确认获得指定工作区权限。手机配对与授权不依赖 JanusX 账号登录、团队账号或组织成员关系；旧账号系统不是新手机链路的信任来源。当前二维码密钥认证 SDP、设备申请及连接期间的授权凭据见[配对握手](../android-pairing-handshake.md)，长期设备信任仍未实现。

首版必须允许手机在连接并获得授权后，真实启动电脑端的 Claude Code。启动应进入 JanusX 的真实终端/进程管理链路，在所选已授权工作区运行电脑上安装的 Claude Code，返回可跟踪的终端实例与进程状态。不得以模拟输出、echo、只打开终端页面或仅附着已有实例替代新启动验收。电脑未安装 Claude Code、登录不可用或启动失败时如实显示结果；CLI 的安装、登录及凭据保留在电脑。

终端输出采用持续流式推送，手机显示启动过程和后续真实输出，并能提交输入且观察实际结果。首次订阅与重连需要输出序号、有限回放和缺口处理；创建与输入操作有稳定请求 ID，重试不能重复启动或重复提交。网络中断或手机离开页面不自动终止电脑端 Claude Code；显式关闭属于独立操作。

手机新建终端后，电脑相应工作区应出现真实终端入口及运行状态；远程面板显示工作区、已授权连接与终端，并能跳转桌面查看。Android 使用终端屏幕渲染处理 ANSI/VT 光标、颜色、清屏、覆盖和中英文字符，不把控制序列或连接日志当作普通输出。竖屏支持适宽、字号调整和横向查看，保留历史滚动；软键盘和旋转不应遮住输入或重复启动终端。关闭创新功能会隐藏入口、停止远程服务并断开手机，电脑已启动的终端继续运行。

业务内容经加密 UDP P2P 通道直接传输，采用 WebRTC DataChannel、ICE/STUN，不启用 TURN 或业务中继。公网信令仅承载连接协商。连接失败应明确提示，不以回环或模拟器结果替代真实异网手机验收。

当前优先完善直连：建连阶段保留信令并有界重试，隔离旧轮次的候选及回调，区分候选收到、实际应用和路径检查应答；保留可用 IPv4/IPv6 路径，不因一次 ICE 失败直接认定运营商封锁或必须中继。TURN 兜底暂不实施，无法直连时如实结束并保留诊断。

远程入口需明确区分同一局域网与异网。异网使用双方可访问的公网 wss 信令，不能把局域网地址或 STUN 映射当作公网信令；多网卡允许选择手机可访问的网卡。失败提示应区分信令未连通、等待电脑协商、UDP 路径失败及等待审批，帮助真机测试定位阻塞阶段。

长期使用需要稳定公网信令入口，由维护方部署并预置，普通用户仅开启、扫码和批准；自建地址仍可配置。当前 Cloudflare Pages 免费入口通过服务绑定复用 Worker，桌面与后续 Android 构建共享默认地址；现有包扫码取得地址。用户报告关闭 VPN 后可连接并发送输入，但手机输出不可见；完整交互、长期连接、配额与网络覆盖仍需验证，不把 HTTP 健康检查或一次连通当作完整验收。临时 Quick Tunnel 只作测试；信令基础设施与终端 UDP 直连分别承担协商和业务传输。

## Acceptance criteria

2026-10-21 真机反馈：用户在 Pages 信令入口、关闭 VPN 后报告连接成功且输入可发送，但 Android 看不到返回内容。因此 AC-3/AC-8 继续未通过，其余完整验收也不由一次连通自动勾选。输出故障优先定位，不将输入回执视为终端输出。

0.1.11 已实现二维码倒计时及隔离新配对的自动轮换、桌面持续阶段显示、安卓页面启动/错误诊断和重载回放。虚拟时钟单测与本机 Electron/Android 模拟器证据维护在配对握手专题；用户确认真机为从一开始空白，尚需新版真机复测，以下完整验收项继续保持未勾选。

- [ ] AC-1: 无需 JanusX 账号或组织，手机扫码、电脑确认后配对；未批准与已撤销设备无法查看或操作终端。
- [ ] AC-2: 手机从异网真实请求新建 Claude Code，电脑观察到新真实终端及对应运行进程，并验证所选工作区正确；请求重试不重复创建。
- [ ] AC-3: 手机连续收到真实 Claude Code 输出，提交输入后看到实际响应；不是合成主机或模拟回显。
- [ ] AC-4: 断线重连可恢复同一终端输出，缺口明确处理，不重复执行输入；断线不结束电脑端进程。
- [ ] AC-5: 真实手机跨网报告选中 UDP 非 relay 路径；覆盖配对拒绝、撤销、启动失败与连接失败场景。
- [ ] AC-6: 远程开关默认关闭，设置关闭后入口和服务均关闭；不能绕过 UI 直接启动，已启动的电脑终端不被结束。
- [ ] AC-7: 默认授权当前工作区，手机新建 Claude 后对应电脑工作区出现终端和运行状态；远程面板可跳转查看。
- [ ] AC-8: Android 真机正确显示连续终端屏幕、中文和控制序列重绘，支持适宽/放大/滚动、软键盘输入和旋转；重连恢复同一终端，输出缺口触发同步。
- [ ] AC-9: 桌面二维码显示剩余有效时间，到期自动刷新，旧码不能用于新的配对；刷新不打断已授权连接、不撤销既有授权、不结束终端进程。
- [ ] AC-10: 桌面在手机连接过程中持续展示信令、UDP 协商、等待批准及授权/失败状态，不要求打开调试工具才能确认进度。

## Future collaboration

用户希望讨论无账号体系下的长期团队连接。候选方向见[无账号团队协作候选方向](../ideas/account-free-team-collaboration.md)：持久设备身份、拥有者审批、工作区角色、撤销和设备恢复，复用 P2P 连接及流式协议。团队协作、长期凭据、离线同步与多设备身份恢复尚未纳入首版验收，也未确认具体方案；长期授权不代表单条连接永远在线。
