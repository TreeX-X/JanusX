# Android 扫码配对与真实远程终端

## Expected behavior

电脑开启远程功能并生成临时二维码，Android App 扫码后申请配对，经电脑拥有者确认获得指定工作区权限。手机配对与授权不依赖 JanusX 账号登录、团队账号或组织成员关系；旧账号系统不是新手机链路的信任来源。设备身份、配对凭据与撤销机制仍必需，具体密钥与协议实现待定。

首版必须允许手机在连接并获得授权后，真实启动电脑端的 Claude Code。启动应进入 JanusX 的真实终端/进程管理链路，在所选已授权工作区运行电脑上安装的 Claude Code，返回可跟踪的终端实例与进程状态。不得以模拟输出、echo、只打开终端页面或仅附着已有实例替代新启动验收。电脑未安装 Claude Code、登录不可用或启动失败时如实显示结果；CLI 的安装、登录及凭据保留在电脑。

终端输出采用持续流式推送，手机显示启动过程和后续真实输出，并能提交输入且观察实际结果。首次订阅与重连需要输出序号、有限回放和缺口处理；创建与输入操作有稳定请求 ID，重试不能重复启动或重复提交。网络中断或手机离开页面不自动终止电脑端 Claude Code；显式关闭属于独立操作。

业务内容经加密 UDP P2P 通道直接传输，采用 WebRTC DataChannel、ICE/STUN，不启用 TURN 或业务中继。公网信令仅承载连接协商。连接失败应明确提示，不以回环或模拟器结果替代真实异网手机验收。

## Acceptance criteria

- [ ] AC-1: 无需 JanusX 账号或组织，手机扫码、电脑确认后配对；未批准与已撤销设备无法查看或操作终端。
- [ ] AC-2: 手机从异网真实请求新建 Claude Code，电脑观察到新真实终端及对应运行进程，并验证所选工作区正确；请求重试不重复创建。
- [ ] AC-3: 手机连续收到真实 Claude Code 输出，提交输入后看到实际响应；不是合成主机或模拟回显。
- [ ] AC-4: 断线重连可恢复同一终端输出，缺口明确处理，不重复执行输入；断线不结束电脑端进程。
- [ ] AC-5: 真实手机跨网报告选中 UDP 非 relay 路径；覆盖配对拒绝、撤销、启动失败与连接失败场景。

## Future collaboration

用户希望讨论无账号体系下的长期团队连接。候选方向见[无账号团队协作候选方向](../ideas/account-free-team-collaboration.md)：持久设备身份、拥有者审批、工作区角色、撤销和设备恢复，复用 P2P 连接及流式协议。团队协作、长期凭据、离线同步与多设备身份恢复尚未纳入首版验收，也未确认具体方案；长期授权不代表单条连接永远在线。
