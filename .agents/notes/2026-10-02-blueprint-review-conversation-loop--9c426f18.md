# 蓝图对话整理为审核文档与持续讨论

## Problem

蓝图右侧对话应帮助用户读取 Note、讨论需求并形成理解。用户点击“整理”后，期望 Janus 根据当前需求与理解产出待审核的修改文档，用户点击通过后才编辑 Note。如果整理结果以聊天回复呈现，文件正文位于输入框上方的折叠区域，用户难以感知已进入文档审核阶段。

整理动作与普通聊天共用调用链时，自动生成的问答容易混入讨论历史；审核文档若只作为输入框上方的折叠附件，用户仍需在聊天回复中寻找修改结果。生成阶段还必须接收已读取的 Note 原文，避免仅凭节点摘要修订文档。

## Expected behavior

将整理作为明确的文档生成动作：Janus 应结合当前讨论、需求约束与范围内 Note 原文生成修改稿，展示整理进度，成功后自动呈现待审核文档。审核区域应突出当前理解、修改理由、涉及的 Note 和修改后完整正文，并允许查看前后差异；不能仅靠一条聊天摘要交付结果。审核与历史采用同栏切换，输入框持续可用。

用户明确要求整理后仍可继续对话，并在后续再次整理和审批。讨论、整理、审核和应用应形成可重复的循环，不能成为只允许向前推进的一次性流程。待审核时应保留可达的对话入口与历史；用户无需先通过或结束任务才能补充需求。继续发送讨论后，沿用现有规则使旧提案与批准失效，清楚提示需要重新整理；仅查看或切换对话视图不应作废提案。再次整理应采用更新后的讨论和有效 Note 基线生成新的待审版本，不自动写入文件。

用户通过后应应用本次审核的确切文件内容并刷新蓝图，不在批准后再次让模型生成正文。应用完成后仍应保留同一会话，允许继续讨论、再次整理、再次审批；下一次整理应读取已应用的 Note 状态，避免重复应用旧修改。无变更、生成失败或取消时应显示明确结果，保留讨论并允许后续重试。

文件版本、源哈希、预览与事务一致性的规则由[文件审批决策](./2026-09-29-blueprint-maintenance-approval-gap--a1b2c3d4.md)持有；承载方式见[主动作栏决策](./2026-09-30-blueprint-action-bar--8b40c7d2.md)。实施范围与验证证据见[文档审核循环实施](./2026-10-02-blueprint-review-implementation--cb4d82c5.md)。

## Scope

“待编辑审核文档”在本需求中明确指待应用的 Note 修改稿。是否允许用户在审核区直接手工编辑正文尚未确认，不作为已确认范围；当前明确支持通过继续对话提出修改意见，再次整理生成新稿。

## Alternatives considered

- 保持现有聊天回复与折叠文件预览：可直接复用全部交互，但整理的主要产物仍不突出，无法满足用户希望直接审阅文档的目标。
- 使用必须通过或取消才能退出的审核弹窗：阶段清晰，但阻碍整理后继续讨论和反复修订，不符合用户明确要求。
- 复用现有生成和文件事务链路，增加文档审核视图与持续对话入口：可保留批准一致性，同时支持反复讨论与整理；需要处理视图切换、版本失效和应用后重新读取基线。

## Acceptance criteria

- [x] AC-1: 右侧对话根据当前有效范围读取 Note 并讨论需求；普通发送不修改 Note。
- [x] AC-2: 点击整理后显示生成状态，并根据当前讨论和 Note 内容产出待审核文档；完成时自动展示文档，不能仅输出普通聊天回复。
- [x] AC-3: 审核视图提供修改理由、涉及文件、修改后完整正文及前后差异入口；只有用户明确通过后才应用其审核的版本。
- [x] AC-4: 生成待审核稿后仍可继续对话，无需先通过、取消或结束任务；发送补充意见使旧批准失效并给出提示，再次整理可生成新的待审核版本。
- [x] AC-5: 审核与对话视图之间的纯浏览切换保留当前有效提案；多次讨论、整理和审批保留同一会话上下文。
- [x] AC-6: 应用完成后刷新蓝图，仍可继续讨论和整理审批；后续生成采用更新后的 Note 基线，不重复应用旧修改。
- [x] AC-7: 生成无变更、失败、取消或源文件过期时显示准确状态，不意外写入，不将旧稿冒充新稿，并允许恢复讨论和重新整理。
- [x] AC-8: 当必要 Note 原文与完整讨论可容纳时，辅助代码证据超出预算不得阻断整理；使用可靠模型窗口、消除重复正文，并实际发送预算内内容。真实必要上下文超限应报告各部分规模，不能静默截断或将其他运行时错误误报为 Note 过大。

## Risks

长 Note 与多文件审核会占用右侧空间，界面应同时保证文档可读和继续对话入口可达。提案、对话与实际文件具有不同版本，视图保留不能使失效批准重新生效。若后续确认手工编辑草稿，还需扩展宿主预览及校验协议，确保最终批准与写入内容一致。

## Verification

两条完整交互、真实临时 Note 事务、异常与布局检查的证据由[实施任务](./2026-10-02-blueprint-review-implementation--cb4d82c5.md#verification)统一记录。模型使用测试替身，真实供应商的生成质量未验证。
