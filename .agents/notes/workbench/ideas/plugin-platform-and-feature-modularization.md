# PI-Desktop 插件调研与 JanusX 功能插件化探索

## Intent

记录用户要求的 PI-Desktop 调研，并分析 JanusX 已有功能如何按插件管理、外部作者能够开发什么。结论是沿用现有贡献协议，逐步形成“稳定宿主能力、官方功能扩展、隔离第三方扩展”的结构。本文是探索建议，未批准逐项迁移、增加权限或改变既有阶段范围，也未实施插件加载器。

当前事实与验收分别归[插件架构需求](../requirements/plugin-architecture-forms.md)、[第三方导入与调试](../requirements/plugin-import-debug.md)；实施顺序归[插件平台分阶段计划](../../planning/plugin-platform-roadmap.md)。既有首版导入只开放有限只读能力，下面的网络、执行、模型、事件和编辑能力均为后续候选，不能视为现有 SDK。

## 用户确认的记录范围

用户已确认将“JanusX 已有功能的插件化管理”和“后续可由用户开发的插件功能”共同保存在本 Note，作为后续规划输入。本次确认针对方向记录，不代表所有功能已经插件化、候选接口已经开放或逐项实施已经排期。

- 已有功能插件化：保留文件树、Git、会话管理和 CPA 的现有扩展基础，继续评估 Markdown／浏览器／预览、Office、知识库／Note／蓝图、备忘录／圆桌、项目启动、助手适配及通知连接器；每项分别明确视图、服务、数据和停用边界。
- 后续用户开发：项目看板与只读分析、文件查看器、开发运维工具、Agent 工具与工作流、外部系统连接器、事件自动化、个人工具及团队模板；按下文所需 API 分阶段开放。
- 平台基础：SDK 与模板、开发目录导入、隔离页面、受限桥、权限管理、日志和重载先形成闭环，包分发和市场继续后置。项目健康看板作为建议的首个双区域示例，具体实现范围尚待规划。

## PI-Desktop 的实际机制

源码基线为 [vastsa/PI-Desktop 的 494b5f7c8f908aaf1f04bd5e86572dd32ec15167](https://github.com/vastsa/PI-Desktop/tree/494b5f7c8f908aaf1f04bd5e86572dd32ec15167)。本次为静态源码和文档核对，未运行该软件，也未执行其测试。

| 环节 | 实现与借鉴点 |
|---|---|
| 插件协议 | `manifest.json` 声明 ID、版本、入口、权限、兼容版本和命令／页面／工具等贡献；独立作者通过协议接入，无需逐插件修改宿主 |
| 安装 | 支持目录和本质为 ZIP 的 `.piplug`；Rust host-core 负责安装和登记，包校验约束路径穿越、符号链接、50 MiB 大小与 2000 文件数量 |
| 运行 | 普通入口在每插件独立的 Electron `utilityProcess` 中执行；宿主注入 `pi` API，通过消息与 `PluginRuntime` 通信 |
| 能力网关 | `pi.*` 调用回到宿主白名单和权限检查；有效权限取声明与授权交集，插件不能通过重载静默扩大网关权限 |
| UI | 普通面板和工作面板页面隔离承载；`renderer.extension` 则动态导入宿主页面、共享宿主 React，属于高风险可信扩展 |
| Agent 扩展 | `contributes.agentExtensions` 可将 TS／JS 模块交给 Agent sidecar 中适配的 `ExtensionAPI`，兼容范围以其支持子集为准 |
| 开发体验 | 软件内模板、开发目录、监听与重载、日志、SDK 类型、`init/check/pack/publish` 工具，组成开发到交付闭环 |

独立进程主要提供进程故障隔离，不是操作系统权限沙箱。PI-Desktop 普通后台入口仍可使用原生 Node API，其 `pi.*` 权限网关不能约束这些直接访问；深度 UI 模块也具有宿主文档访问能力。JanusX 应借鉴协议和开发闭环，保持既有“不把第三方 JS 直接放入主进程、不暴露完整 renderer bridge”的边界。

普通插件交付编译好的 JS／HTML／CSS，不能依赖宿主安装 npm 或编译 TS；“导入 pi 扩展”有独立、有界的依赖安装例外。其 SDK 和 Devkit 的 package.json 标记为 private workspace 包，不能假定已提供公共 npm 开发入口。根许可证为 LGPL-3.0，直接复用源码应另行核对具体文件和分发义务；本建议复用架构思想。

固定基线证据：[开发指南](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/docs/plugin-development.md)、[安装器](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/crates/host-core/src/plugins/install.rs)、[运行时](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/apps/desktop/electron/main/plugin-runtime.ts)、[插件进程](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/apps/desktop/electron/main/plugin-host-process.mjs)、[UI 加载器](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/apps/desktop/src/plugins/renderer-host/loader.ts)、[安全规范](https://github.com/vastsa/PI-Desktop/blob/494b5f7c8f908aaf1f04bd5e86572dd32ec15167/docs/spec/07-plugins/04-plugin-security.md)。

## JanusX 的现状与分层建议

现有 [types.ts](../../../../src/renderer/src/extensions/types.ts) 和 [registry.ts](../../../../src/renderer/src/extensions/registry.ts) 已有可信 React 视图贡献、同步激活、停用清理、中部／右侧位置和应用级／项目级作用域。[builtins.tsx](../../../../src/renderer/src/extensions/builtins.tsx) 已注册文件树、Git、会话面板，[cpa.tsx](../../../../src/renderer/src/extensions/cpa.tsx) 已注册 CPA 管理页。这证明界面贡献协议可复用，不代表外部插件包已经可导入。

建议分三层管理。宿主提供窗口布局、项目身份、文件事务、进程与会话生命周期、凭证、审批、审计和数据持久化。官方功能扩展组合宿主服务形成工具页面，可默认启用或按需启用。第三方扩展通过隔离页面和授权 API 添加自己的功能，不能直接使用内部 Zustand store、任意 IPC 或其他插件私有数据。

“插件化”应分别判断入口是否可隐藏、视图是否可卸载、后台能力是否可停止、安装包是否可移除。当前内置视图的注册／停用不是完整功能的卸载：服务可能仍被其它功能使用，插件代码仍随主应用分发。移成独立下载包是更后的交付选择。

## 已有功能的插件化适配

| 已有功能 | 适配判断与合理边界 | 后续工作 |
|---|---|---|
| 文件树、Git、会话管理 | 已为内置视图扩展；文件服务、Git 操作和会话执行仍属宿主 | 插件管理页及持久化开关；保持现有调用方、稳定 ID 和偏好 |
| CPA | 已为官方页面扩展；后台下载、启动、密钥处理由固定宿主服务负责 | 可作为官方集成示例，不能当作第三方任意程序执行模板 |
| Markdown、浏览器与文件预览 | 适合可注册页面／查看器；文件窗口、Tab、草稿和浏览器权限仍属宿主 | 设计 viewer 匹配、优先级、回退和编辑保存协议；当前 FileViewerContent 仍有类型分支 |
| Office | 适合官方可选功能包：预览、导出、模板入口 | OfficeCLI 安装、文件监听和执行权限继续受宿主控制；关闭预览不等于结束所有任务 |
| 项目启动、Docker、HTTP 工具 | 项目启动已有能力；Docker／HTTP 属已记录的未实施工具方向，适合扩展页面和领域适配 | 进程监督、端口、凭证和写操作由宿主授权；不把未实现方向记为可用功能 |
| 知识库、Note、蓝图 | 检索页、可视化、导入导出、领域模板适合插件；身份、关系、事务和索引一致性仍由宿主维护 | 明确只读 DTO 与受控变更 API，防止扩展直接写内部库 |
| 备忘录、圆桌 | 页面、角色与流程模板适合官方扩展；备忘录耐久、运行调度和执行授权保持集中 | 先解开 UI 与业务状态依赖，再讨论完整功能开关；不能仅卸载组件就声称任务停止 |
| 助手、模型供应商、CLI 适配 | 人设／提示／工具及供应商适配有扩展价值；已有内部 registry 不等于公共插件协议 | 模型调用由宿主代发，密钥不交给插件；CLI 启动和输出解析需版本化适配契约 |
| 通知与外部服务 | 通知渠道、消息格式、外部系统连接器适合扩展 | 保留宿主事件策略、去重、凭证和用户授权；增加网络及后台能力后再开放第三方 |
| 终端、工作区、编辑器核心、远程连接、更新与权限系统 | 可向扩展提供受控服务或附加 UI；首阶段保留宿主基础职责 | 不提供可被任意插件替换的执行授权链、任意终端注入或更新器 |

迁移前必须识别真实消费者和依赖。停用面板仅卸载视图；停止扩展应清理它自己拥有的订阅、计时器和任务。正在运行的终端、共享服务、未保存编辑及后台任务需有明确归属与关闭策略。永久数据仅在用户显式选择删除时清理，不能随页面关闭消失。核心依赖的官方扩展可标为必需或受依赖约束，不能让一键禁用破坏现有会话。

## 外部作者可以开发什么

以下均为插件平台开放后的产品机会；当前尚无外部加载器。首版只覆盖现有导入需求的只读接口，后续类别需新增贡献点与授权。

| 阶段与插件类型 | 用户能开发的具体功能 | 最低宿主能力 |
|---|---|---|
| 首版：自有页面 | 番茄钟、离线计算器、团队说明页、项目清单、个人工作台 | 中部／右侧视图、主题、插件私有 KV、项目上下文 |
| 首版：只读文件分析 | package.json 依赖摘要、项目约定检查、TODO 列表、文档目录、构建配置概览 | 工作区限定文件读取；大目录列表／搜索若无首版 API，需后续补充，不能由插件任意扫描磁盘 |
| 后续：领域查看器 | CSV／JSON 检查器、日志分析、数据库结构图、接口文档、专业格式预览 | 文件打开贡献点、匹配与回退、受限文件读取；编辑类另需保存 API |
| 后续：开发与运维工具 | 测试面板、Docker／Compose、HTTP 调试、部署状态、CI 结果 | 授权网络／执行、受监督进程、取消、日志；连接凭证由宿主管理 |
| 后续：Agent 工具与工作流 | 项目规范检查工具、团队知识查询、文档生成、发布检查、圆桌流程模板 | 工具 schema、风险／审批、宿主模型代发、取消／超时和输出追踪；普通 UI 插件不会自动成为 Agent 工具 |
| 后续：外部系统连接器 | GitHub issue／PR、GitLab、飞书、Notion、工单与团队知识同步 | 域名授权、凭证引用、宿主网络代理及后台任务；双向同步额外定义冲突处理 |
| 后续：事件自动化 | 测试结束生成摘要、会话完成提醒、Git 变更生成说明、文件变动检查 | 有版本的事件协议、作用域、去重、限流、任务归属；消费事件不自动取得写权限 |
| 后续：个性与团队规范 | 主题令牌、命令、项目模板、技能包、检查规则 | 专用声明式贡献点、校验和清理；不开放任意全局 CSS／宿主 DOM 修改 |

JanusX 的价值是把项目文件、工作台页面、会话、Agent 和产物连接起来。首批插件宜展示这个组合：只读项目健康看板提供中部详情与右侧摘要；模板同时演示项目切换、私有状态、资源释放和授权失败。执行型示例另开阶段，不能为了演示“测试后让 Agent 总结”而绕过首版网络／执行／模型限制。

作者开发流程建议为“从模板创建 → 在 JanusX 打开目录并编辑 → 加载开发目录 → 授权 → 使用与查看日志 → 重载 → 校验与交付”。使用软件内的终端和编辑器开发插件可复用现有能力；SDK 不应要求作者修改 JanusX 源码、导入私有 store 或手写内部 IPC。模板至少要有一个不依赖内部仓库即可运行的外部项目。

## 建议顺序与待裁决问题

继续现有 S4，只完成 SDK／清单、目录导入、隔离 UI、有限只读桥、管理与调试闭环；随后补已有官方视图的可理解管理界面，再按实际需求新增命令、viewer、工具和事件协议。S5 包分发与市场保持既有后置依赖，不以迁移所有模块为启动条件。建议暂不移动全部功能源码到 packages，先把所有权、API 和停用语义做清楚。

仍需决定：官方功能哪些必需、哪些可选；首批第三方插件以纯工具页面还是项目只读分析为主；官方功能包未来是否独立更新；执行型插件采用 MCP、受限运行时或另行明确的可信开发模式。它们属于后续产品和架构选择，本次记录不替代用户裁决。

## Verification

核对当前扩展定义、内置注册、CPA 入口、右侧注册表、文件查看器分支、领域 IPC 注册和现有规划／需求。已有文件树、Git、会话、CPA 视图为代码事实；其余矩阵为适配判断，不是已完成迁移或性能收益证明。本文仅变更维护文档，不更改应用代码。
