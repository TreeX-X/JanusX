# Note drawer Markdown toolbar and file glyph

Planned presentation change: [Markdown 独立 pane 与顶栏工具分组](./markdown-pane-entry.md) moves the Markdown entry and editor out of the bottom drawer into a central pane, while retaining the editing capabilities documented here. That migration is not implemented; this decision still describes the current drawer. The bottom runtime telemetry view keeps its own responsibility.

## Problem
The bottom drawer in `TerminalArea.tsx` switches between the runtime telemetry view and the note view with two filled chips: the active chip is an accent-tinted block and the idle chip a near-black block, so the switch reads as a status badge instead of a control. Opening the drawer also swaps its background from the terminal canvas to the lighter shell chrome, so a grey slab rises under the terminal, and the note pane inside paints its own container, editor and buttons with hand-picked near-black values (`#0d0f10`, `#0a0c0d`, `#17191b`) that match neither the slab nor the canvas. The editor itself is a bare textarea behind an Edit/Preview toggle: no formatting affordances, no shortcuts, no list continuation, so every Markdown marker is typed by hand, and the toggle throws away the side-by-side reading that a drawer this wide can afford.

### Conventional file glyph for the drawer's Markdown view
The bottom drawer in `TerminalArea.tsx` switches between the runtime telemetry view and the Markdown note view with two tabs pinned to the right of the drawer header. The runtime tab carries lucide's `Activity`, a single four-segment polyline with no container, while the note tab carries `NotebookPen`, which draws six separate shapes: a page with an open corner, four binding ticks down its left edge, and a diagonal pen crossing the whole glyph. `TabStrip.module.css` renders the tab icons at 12px, and at that size the four ticks — spaced four units apart on lucide's 24-grid, so two pixels apart once scaled — merge into a solid smudge along the page's left edge, while the pen adds a sixth direction of movement to a glyph already carrying five. The two tabs therefore have wildly different optical weights sitting side by side in the same 28px header.

The same `NotebookPen` is reused as the note pane's empty-state mark in `QuickNote.tsx`, rendered at 22px on a 22px box with `strokeWidth` 1.5 and the color `rgba(255,255,255,0.18)`. There the ticks and the pen read as noise rather than meaning, and the glyph's mass comes mostly from the page outline rather than from anything that says "Markdown".


## Decision
The expanded drawer is a black tray. `globals.css` defines `--shell-drawer` at `#0c0c0e`, one step below `--shell-void`, and the drawer container takes it while open and keeps `--shell-canvas` while collapsed, so the closed strip still matches the terminal canvas and the open tray sinks below it. This is the one surface outside the ramp that the user sees as black; the user chose it over the ramp's lighter chrome. Every panel inside the tray is transparent with a 1px `--shell-border` frame and hairline dividers: the runtime section, the note pane, its card list, its editor and its preview all show the tray through, so the tray reads as one black surface with lines on it rather than a stack of grey plates.

`TabStrip.module.css` under `components/ui` holds one tab strip for both switches: no container, no fill, text on `--shell-dim` that brightens to `--shell-muted` on hover, and a selected tab that turns to `--shell-text` with its icon in the accent and a 2px accent bar along the bottom edge. No segment ever carries a background, because in this shell the accent earns bars, borders and text only, and a neutral filled segment still reads as a grey block. `DrawerViewTabs` in `quick-note-behavior.ts` renders that strip with an activity icon for the runtime view and a notebook icon for the note view, sized to the 28px drawer header so the bar sits on the header's bottom edge; the caller passes localized labels (`terminal:tab.view.runtime` reads 用量 / Usage, `terminal:tab.view.note` reads Markdown) and the view id remains the fallback label, so the tabs render without an i18n provider in unit tests. The strip stops click propagation itself so a click on its padding never toggles the drawer, and `TerminalArea.tsx` reserves `pr-52` in the drawer header for it.

Inside the note pane the selected card carries the same 2px accent bar on its left edge and bright text, with no fill; hover on a card is a 3% white wash that disappears on leave. The title field has no background and shows a 1px accent underline only while focused. Toolbar icons are 24px transparent buttons that wash on hover, the footer buttons are 1px outlines with no fill, and the export popup is the only filled surface because a menu needs one. The list shows a stripped first-line excerpt and the update age per card, and it folds away when a `ResizeObserver` measures the pane under 520px, because below that width the list would leave the editor narrower than its toolbar.

Editing has three modes in a second tab strip: edit, split and preview. Split renders the textarea and the preview side by side; preview alone hides the toolbar. The preview keeps `MARKDOWN_COMPONENTS` and the `markdown-preview` class, whose ownership stays with [markdown preview local assets](./markdown-preview-local-assets.md). The toolbar offers fifteen actions in four groups: heading levels one to three; bold, italic, strikethrough and inline code; bullet, numbered and task lists plus quote; link, fenced code block, table and divider. Bold, italic, inline code and link answer to Mod+B, Mod+I, Mod+E and Mod+K, strikethrough to Mod+Shift+X; every button title carries its shortcut in the platform's notation. Enter inside a list item continues the list with the next marker or ordinal and Enter on an empty item leaves the list; Tab and Shift+Tab indent and outdent the caret line or the selected lines by two spaces. The footer shows a word and character count, where each CJK character counts as one word, next to the export menu and the paste button.

`quick-note-format.ts` owns the editing rules as pure functions and never touches the DOM: each action resolves to a `NoteEdit`, which is the replaced range, the replacement text and the selection the editor must end with. Inline marks wrap the selection, or the word around a collapsed caret, and remove the markers when the selection or its surroundings already carry them. Line marks apply to every non-blank line in the selection and remove themselves when every such line already carries the mark; a heading action replaces an existing level instead of stacking hashes, and a list action converts between list kinds. Blocks always land between blank lines, because a `---` glued to the previous line turns that line into a setext heading and a table swallows every following non-blank line as a row. `QuickNote.tsx` applies an edit by selecting the range and calling `document.execCommand` with `insertText`, or `delete` when the replacement is empty, so the change enters the textarea's native undo stack and Ctrl+Z reverts one toolbar action at a time; when `execCommand` is unavailable or the resulting value differs from the expected one, the pane writes the value to the note store and restores the selection in a layout effect after React commits the controlled value. Without the execCommand path, every toolbar action would clear the browser's undo history for the field.

### Conventional file glyph for the drawer's Markdown view
`components/ui/MarkdownIcon.tsx` is a new glyph that keeps the conventional file shape and puts an M where a text file's lines would sit. It draws three paths on lucide's 24-grid with the same round caps and joins: the page with its folded corner (`M15 2H6a2 2 0 0 0-2 2v16a2 2 0 0 0 2 2h12a2 2 0 0 0 2-2V7Z` plus the fold `M14 2v4a2 2 0 0 0 2 2h4`), then the M `M7 18v-8l5 5L17 10v8`. The fold is the part that makes the shape read as a file rather than a box, so it stays; the binding ticks and the pen are what made the glyph busy, so they go. The M spans `x` 7 to 17 and `y` 10 to 18, centred on the page, so it takes the room `FileText` would give its three text lines and carries the Markdown meaning in a single letter.

Two earlier candidates were built and rejected in review. A bare markdown mark with no page at all — the `M` and a down chevron — is the lightest possible reading and matches `Activity`'s container-free style, but the user judged it too minimal: five line segments floating in a 28px header read as a stray glyph rather than a view. Dropping the fold and keeping only a rounded rectangle was rejected for the opposite reason, because without the corner the shape stops reading as a file. The conventional page plus an M inside is the version that satisfies both constraints the user stated: it should look like a normal file icon, and it should still represent Markdown.

A third revision removed the down chevron from beside the M, leaving the page, the fold and the letter alone. With the chevron gone the M grows from `x` 5 to 12 up to `x` 7 to 17, which both centres it on the page and widens it to about 5px at the tab's 12px, so the letter stays legible as the glyph's only interior mark. The chevron was the second of the two interior marks and the user asked for the file and the M only; the letter on its own is enough to name the format, and one interior mark is one fewer thing to resolve at 12px.

`MarkdownIcon` exposes `className`, `strokeWidth` and `aria-hidden`, matching the props the two call sites already pass to a lucide icon, and takes `strokeWidth` as `number | string` so it can sit in the same record as `Activity`. `DrawerViewTabs` in `quick-note-behavior.ts` types `DRAWER_VIEW_ICONS` as `Record<DrawerView, ComponentType<MarkdownIconProps>>` and maps the note view to it; the runtime view keeps `Activity`. The tab strip's own color rules still apply, because the glyph inherits `currentColor` and takes `--shell-dim` at rest and `--shell-accent` when selected, exactly as the lucide icons did. `QuickNote.tsx` renders the same glyph in its empty state at `strokeWidth` 1.4.

The empty-state box moves from 22px to 24px and its color from `rgba(255,255,255,0.18)` to `rgba(255,255,255,0.22)`. The new glyph has less mass than `NotebookPen` — no ticks, no pen — so the original tuning left it nearly invisible on the black tray; one step of size and one step of opacity restores the balance without making the decorative mark compete with the empty-state text on `--shell-dim`.



## Alternatives considered
- A segmented control with a neutral raised selected segment (`--shell-active` fill, 1px container) — strongest case is that it matches the raised selection the settings navigation uses and gives the selected state a clear shape. The driver that rules it out is the user's verdict on the shipped version: a filled segment is still a grey block inside a control, and the underline strip conveys the same state with a bar and text alone.
- Keep the drawer on the shell chrome and lift the panels above it — strongest case is that it follows the surface ramp in `globals.css`, where nothing the user sees is black. The driver that rules it out is the user's explicit requirement that the expanded page be black; a lighter slab under a dark terminal is what they asked to remove.
- Mount Monaco for the note editor — strongest case is that `FileEditor` already ships Monaco with undo, find and multi-cursor, and a Markdown language mode exists. The driver that rules it out is the boot cost and worker set-up for a scratch pad inside a 380px drawer, plus Monaco's own keybinding and theme surface that the toolbar would have to bridge; a textarea with execCommand keeps native undo and IME composition for free.
- A contenteditable rich-text editor that hides the markers — strongest case is that the writer never sees `**` or `#`. The driver that rules it out is that the note's payload is pasted into terminals and exported as Markdown text, so the source is the product and must stay visible and exact.
- Do nothing / reuse — keeps the grey slab, the filled chips and the bare textarea. The cost is the visual break with the terminal canvas and the manual markup on every line, which is what the drawer's note view exists to remove.

### Conventional file glyph for the drawer's Markdown view
- Keep `NotebookPen` — strongest case is that it is a stock lucide icon with no maintenance cost and it does name a notebook. The driver that rules it out is the user's own reading of the shipped result: at 12px the ticks and the pen turn the tab into smudge, which is the specific defect the change was asked to remove.
- A bare markdown mark with no page — strongest case is that it is the lightest glyph possible, matches `Activity`'s container-free style, and needs only two paths. The driver that rules it out is the user's verdict on the live build: too minimal, and it stops reading as a file.
- Lucide's `FileText` — strongest case is that it is the conventional file icon with zero new code. The driver that rules it out is that its three generic text lines say nothing about Markdown, and the user asked for a glyph that still represents the format.
- A rounded rectangle with an M inside and no fold — strongest case is that it drops to two shapes and gives the letter more room. The driver that rules it out is that the folded corner is what makes the shape read as a file rather than a box, which is the property the user asked to keep.
- The page, the fold and the M-plus-arrow, with the arrow kept — strongest case is that the M-plus-arrow is the markdown logo, so the glyph names the format unambiguously at any size. The driver that rules it out is the user's request to remove it: two interior marks at 12px is one more thing to resolve than they wanted, and the file plus the M was enough.
- Reuse `FileTypeIcon`'s markdown glyph from the file tree — strongest case is that it is the same "page plus mark" idea the user already sees on every `.md` row, so the drawer tab would match the tree. The driver that rules it out is that `FileTypeIcon` bakes in a `colorToken` class that paints the glyph with the file-kind color, which would break the tab strip's dim-to-accent treatment, and it is drawn on a 16-grid that scales the interior mark down to roughly 4.6px at the tab's 12px.


## Consequences
- **Gains**: The drawer opens as a black tray under the terminal instead of a grey slab, the view switch and the mode switch read as text with a bar, and nothing inside the tray carries a fill except transient hovers and the export menu. Markdown writing gets a toolbar, shortcuts, list continuation and indentation, and a split view for reading while writing; each toolbar action is one undo step.
- **Costs and limits**: `--shell-drawer` is a deliberate exception to the surface ramp; any new panel inside the drawer must stay transparent or the tray turns back into plates. The 2px bar is the only shape of the selected tab, so a tab strip needs a bottom edge to sit on and cannot float in free space. `document.execCommand` is deprecated in the web platform though supported by Chromium and therefore Electron; when it returns false the fallback path still applies the edit but the browser's undo stack does not include it. Toolbar actions read the raw textarea selection, so in split mode they act on the left pane only and the preview stays read-only. The editing mode lives in component state and resets to edit whenever the drawer remounts the pane. The 520px compact threshold is a constant, not derived from the toolbar's measured width. Shortcuts are intercepted only while the textarea has focus, and an Electron menu accelerator on the same key would win if one is added. The textarea captures Tab and Shift+Tab for indentation, so keyboard focus leaves the editor through the mouse or the shell's own focus shortcuts, never through Tab order. The word count treats each CJK character as a word, which overstates counts for long compounds. The drawer heights, the drag handle and the runtime cards stay owned by [runtime drawer cards and drag height](./runtime-drawer-cards-resize.md).
- **Verification**: `npx vitest run tests/unit/note` passes 49 tests, including `quick-note-format.test.ts` for the splice rules and `quick-note-view.test.ts` for the tab markup, the header reservation and the export menu. A Vite and Playwright harness rendering `QuickNote` with `DrawerViewTabs` on the tray at 1180px and 640px confirms in Chromium that bold via the toolbar wraps the selection and keeps it selected, Ctrl+Z reverts it, Enter after a task item inserts `- [ ] `, Ctrl+K inserts a link, the tray computes to `rgb(12, 12, 14)`, both tabs compute to a transparent background, and the selected tab's 2px underline computes to the accent.

### Conventional file glyph for the drawer's Markdown view
- **Gains**: The Markdown tab drops from six shapes to three and its optical weight now sits close to the runtime tab beside it, so the two view switches read as one control instead of two different kinds of mark. The glyph keeps a conventional file silhouette while still naming Markdown through the M. The empty-state mark loses the ticks and the pen and gains one step of size and opacity, so it reads as a quiet watermark rather than a smudge. No color rule changed: the glyph inherits `currentColor` and the existing tab strip and empty-state treatments still govern it.
- **Costs and limits**: `MarkdownIcon` is a hand-rolled glyph rather than a stock icon, so it will not follow a lucide upgrade the way the other tab icon does; the same is already true of `WorkbenchIcon` and `FileTypeIcon` in this codebase. The M is the glyph's only interior mark, so the format is named by a single letter rather than by the markdown logo's M-plus-arrow; a reader who does not already associate a lone M with Markdown gets only the tab label to go on. The 24-grid geometry was chosen for the drawer tab; if a future call site needs the glyph below 12px the M should be enlarged or dropped rather than the whole glyph scaled. `DrawerViewTabs` now depends on `ComponentType` from React for the shared record type, which is the only reason the icon's `strokeWidth` prop is widened to `number | string`. The empty-state size and opacity are hand-tuned constants with no measurement behind them, matching how the rest of `QuickNote.module.css` sets its 24px icon buttons.
- **Verification**: `npm run typecheck` passes, including the `ComponentType<MarkdownIconProps>` record that holds `Activity` and `MarkdownIcon` together. `npx eslint` on `MarkdownIcon.tsx`, `QuickNote.tsx`, `quick-note-behavior.ts` and the note directory reports nothing. `npx vitest run tests/unit/note` passes 49 tests, with `quick-note-view.test.ts` still asserting that the drawer tabs render an `<svg` and keep their tab and panel associations. `npm run test:unit -- --run` passes 251 files and 1796 tests; `tests/unit/task-contract-adoption.test.ts` failed on two of four full-suite runs by exceeding its own 5000ms command timeout on a `git clone --no-local` step under load, and passes both in isolation and in the other two runs, so it is unrelated flake in a main-process test that touches none of the files changed here. The visual result was reviewed by the user in the running app across three revisions: the bare markdown mark was rejected as too minimal, the page plus M-plus-arrow was accepted in shape, and the chevron was then dropped at the user's request to leave the file and the M, which is the version recorded here.
