# 服务集成与 CPA 账号管理复用

## Intent

JanusX 通过可信扩展接入 CLIProxyAPI（CPA）的既有管理页，Figma 仍为后续候选。通用扩展基础与内置工具迁移已交付 S1、S2；S3 提供应用全局的 CPA 连接设置和中部页面。服务集成增强工具连接、配置和工作台入口，保留原 CLI 的会话管理、交互和执行逻辑。

CPA 首版连接已有实例，复用其管理前端，不重建账号面板。JanusX 仅保存管理页地址；管理密钥由用户在原版页面输入，记住登录由该页面负责。宿主不读取或注入管理密钥，不复制账号或刷新令牌，不配置模型调用凭据。未来如需原生额度摘要或模型 API 连接，再单独确定接口、凭据和供应商覆盖。

CPA 只覆盖接入该实例的账号与调用。CLI 直接使用自己的登录时，不能假定 CPA 已观察到其身份、请求或额度。只有出现不经 CPA 的账号需求，或工作台确实需要跨实例、跨服务摘要时，再评估只读账号视图。

Figma 作为独立服务集成候选：工作台承担连接状态、设计文件关联和打开入口；Agent 读取设计或执行操作需另行核对所选 API/MCP 能力及各 CLI 的接入方式。CPA 的模型网关与账号管理不替代 Figma 授权。

先以内部集成接口验证实际需求，再评估第三方插件开放。不同集成按实际能力声明配置、状态查询、操作入口及工具接入，不要求全部实现 Harness 会话协议。此探索关联既有 [插件架构提案](./requirements/plugin-architecture-forms.md) 与 [插件导入和调试提案](./requirements/plugin-import-debug.md)，不改写其未完成验收或授权边界。

交付顺序及测试证据归[插件平台分阶段计划](../planning/plugin-platform-roadmap.md)。文件树、Git、会话管理继续由内置定义与原宿主服务提供；CPA 使用相同视图贡献协议。当前生命周期由可信代码控制，尚无插件管理页与跨启动停用偏好；第三方导入与市场归后续阶段。

## Proposed surfaces

设置中的“服务集成”位于“应用设置”分组，与终端管理并列，当前配置 CPA 管理页地址并提供“保存并打开 CPA”。后续“插件”页再负责安装、启用、更新和卸载；服务连接和插件安装状态分别维护。

用户已确认中部工作区和右侧工作区均开放为通用插件贡献入口。中部用于需要较大空间和持续操作的页面，右侧用于紧凑工具及当前项目、文件或选区的辅助信息，轻量状态入口用于状态摘要及打开完整页面。插件可以仅提供其中一种视图，也可以同时提供两种，不要求所有插件都有界面。各界面沿用现有设置与工作台的主题令牌、字号、留白和细分隔线，保持简洁，不为每项服务另设一套卡片与视觉语言。

目标插件清单声明视图身份、标题、图标、页面入口、承载位置及应用级或项目级作用域，宿主按声明自动注册入口；接入已支持的能力不需要逐插件修改主程序。S1 已支持可信代码定义的视图注册、宿主入口、打开与关闭、内存快照恢复、停用清理和局部错误处理。插件作者维护页面内容及业务状态；第三方清单字段、独立 SDK、权限和受限通信仍待后续阶段实现，不能从可信扩展接口推导为已向第三方开放。

插件包自带页面与外部服务网页分别采用受限的承载及权限规则，共用视图注册机制；外部网页不因此获得 JanusX 插件桥或被作为远程插件代码加载。同一插件同时提供中部与右侧视图时，可通过宿主提供的受限接口共享业务状态；自动搬移视图、跨容器拖拽及双视图并行保活不由本次方向确认自动承诺。

CPA 是官方集成，待市场建立后可作为推荐项。主要用途为查看管理前端提供的额度及重置次数、时间等信息，转 API 按需使用。`janusx.cpa` 贡献应用级中部视图 `extension:janusx.cpa/management`，通过设置或中部 `+` 菜单打开；切换项目转移同一页面身份，原生网页会话复用。首版无原生右侧额度摘要，也不安装、启动或升级 CPA。

## CPA connection and session

默认地址为 `http://127.0.0.1:8317/management.html`，自定义路径可直接配置。仅接受 HTTP／HTTPS，拒绝地址中的用户名、密码和查询参数；无协议的回环地址按 HTTP，其余按 HTTPS，根路径自动补管理页。全局配置只写入 `cpaSettings.managementUrl`，损坏的旧地址回退默认值以便修复。

中部通过原生 `WebContentsView` 加载既有网页，不使用 iframe 或删除嵌入限制响应头。CPA 按地址 origin 的 SHA-256 前 24 位选择 `persist:janusx-cpa-*` 独立持久分区，与普通浏览器及其他 CPA origin 隔离。同一 origin 的路径共用登录；关闭页面释放视图，保留该分区的网页登录数据。跨项目、重新打开与应用重启可复用页面自己记住的登录。

网页没有 preload、Node 或 JanusX 完整桥，启用 sandbox、contextIsolation 与 webSecurity；固定 CPA IPC 仅允许主窗口主框架调用。HTTP／HTTPS 弹窗转为页面内标签，自定义协议和本地文件导航被拒绝；OAuth 等需要系统窗口的流程尚未验证，顶部保留“在浏览器打开”。打开对话框时原生视图让位，关闭和停用释放界面资源。此承载规则不构成第三方插件的权限桥。

管理密钥的持久保存取决于 CPA 原前端的“记住密码”实现，存于该独立浏览器分区；本功能不承诺宿主安全存储或系统钥匙串保护。宿主模型凭据不使用这份管理登录。

## Figma direction

Figma 候选方案分为服务连接、项目关联和 Agent 工具三部分：设置管理授权及连接状态，项目保存设计文件关联，中部打开设计内容，右侧按需展示关联文件或选中内容。Agent 通过所选 API/MCP 获取设计上下文或执行受支持的操作，并适配各 CLI 的工具配置。打开网页、通过 MCP 访问设计、运行 Figma 插件是不同能力；Figma 插件依赖 Figma 自身宿主，不能当作 JanusX 插件直接导入。网页嵌入、OAuth、读写能力和文件访问范围均未验证，不能由“已连接”推导出完整编辑能力。

## Plugin format and import direction

跨软件不存在可直接通用的完整插件包格式。VS Code、Figma 等生态各自定义宿主 API 和运行环境；MCP 可作为工具接入协议，但不自动提供 JanusX 界面、安装生命周期或工作区入口。插件市场负责发现、分发和更新，插件清单与宿主契约决定包的兼容性，应先验证包格式和加载闭环，再建设市场。

沿用现有提案的起步方向：JanusX 自有插件通过本地文件夹导入，包内包含 `manifest.json` 及构建后的界面资源，清单声明身份、版本、宿主兼容范围、权限和贡献入口。先实现导入、校验、授权、启用、使用、禁用及卸载，再评估 ZIP、远程源和市场分发。该格式及导入能力目前仍是提案，不代表已经实现，也不承诺直接兼容其他软件的插件。

现有导入草案限制首批第三方插件的网络、凭据及写入能力。CPA、Figma 优先通过官方内部集成验证连接、授权和真实工作流，再提炼第三方宿主能力；若需扩大插件权限，应明确修订原提案并补充验证，不通过单个集成绕过边界。

## Reference and limits

参考 CodexHost 提交 `1aa9f65d6abf8f15b3a390f10de0b97ad85ae847` 的 [账号设计](https://github.com/BytePioneer-AI/codex-host/blob/1aa9f65d6abf8f15b3a390f10de0b97ad85ae847/docs/product/codex-accounts.md)：当前原生 Codex 登录仍由官方管理，账号页展示身份与额度，并允许将兼容本地授权一次性复制到 Pi 的独立 Provider。凭据复制不是持续同步，共用 refresh token 的多个客户端可能互相影响登录；此实现不作为 JanusX 必须复制凭据的需求。

只读查看 CPA 提交 `0d18d3b365be000eeaee7de4615f9da596b2059d` 的 [项目说明](https://github.com/router-for-me/CLIProxyAPI/blob/0d18d3b365be000eeaee7de4615f9da596b2059d/README_CN.md)，其中提供 [管理 API 文档入口](https://help.router-for.me/cn/management/api)。S3 兼容性验证使用 [CLI Proxy API Management Center v1.26.5](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/releases/tag/v1.26.5) 的原版 `management.html`，SHA-256 为 `57558cd023475674634a114824b014d3e5ac161f6f3791e3d86b6adab962a700`。该版本要求 CPA 8.0.0 及以上，调用 `/v8/management`；这不是 JanusX 对所有前端版本的兼容承诺。

桌面验证将原版前端连接本地模拟管理 API，仅验证内嵌渲染、登录请求、配额页导航与前端登录恢复。未部署真实 CPA 后端，未验证供应商额度、账号 OAuth 或真实重置操作。前端可提供的重置字段因供应商而异，不能承诺每个账号均支持重置次数；调用统计不等于供应商剩余订阅额度。
