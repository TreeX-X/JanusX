# 个人画像与记忆工作台：保留范围与界面方向

## Intent

用户确认个人画像有必要保留，并提出原知识库工作台是否可留给个人画像。本篇负责个人能力与工作台的后续边界；产品归属见[当前方向](../blueprint/product-direction.md)，讨论编号与阶段见[交付计划](../blueprint/evolution-roadmap.md)。保留方向已确认，工作台名称、布局和记忆机制重构深度仍为提议。

## 当前范围（已确认）

当前开发与优化以蓝图为主线。用户明确将个人画像的进一步产品讨论放到后续；本轮只安排个人画像的模块化剥离，以及配合蓝图重构、工程知识库退出所必需的代码维护。个人画像的新机制和界面设计不作为蓝图交付的前置条件。

模块拆分应厘清个人采集、记忆存储、配置、处理/召回及界面入口的职责，复用必要的共享基础并通过明确接口连接。具体拆分及共享能力保留由主 Agent 按实际依赖判断，并在后续持续维护；旧工程专用资产按已确认策略删除清理。拆分不要求另起进程、复制共享队列或立即搬迁个人数据。必要维护包括解耦工程专用依赖、修复受影响调用和兼容入口，以及验证现有开关、采集、确认、纠正、遗忘、召回和数据仍可使用。

已讨论的仅采集用户输入、覆盖内置对话与所有已识别 Agent 终端、开启画像即自动接入 Hook 等方向继续保留，作为后续个人画像建设依据；新增接入能力、提取节奏、记忆自动确认、画像推断、召回优化和完整工作台重做暂不展开。蓝图实施中只处理维持既有个人功能所需的 Hook 兼容，不把这些新增能力加入本轮验收。

## 已确认与现有基础

工程知识与蓝图融合不取消个人画像及个人记忆。当前[分域控制](memory-domain-controls.md)已有个人独立开关、设置、确认、纠正、遗忘和对话召回边界；模块文档继续记录真实实现。工程专用入口已退出，共享队列、个人存储、模型基础和用户来源路径继续保留。

个人信息不因界面整合自动成为项目 Note 或进入工程 MCP。现有工程证据参与个人习惯推断的可选路径需要在工程退出时单独处理：保留时须说明新来源及授权；取消时明确呈现能力变化，不能为维持该路径暗中保留工程采集。

## Hook 采集与自动接入

已确认个人画像保留 Hook，采集范围收缩为用户实际提交的消息，同时覆盖 Janus 内置对话和所有已识别的外部 Agent 终端。开启个人画像功能即自动配置并启用这些来源的用户输入采集，无需用户逐个终端手动接入 Hook，也不依赖工程知识库或蓝图自动审核开关。本节记录后续产品行为，未改变当前采集实现或已有数据。

建议在进入个人采集队列前筛出用户输入，不采集 Agent 回复、工具输出、代码变更或执行日志作为个人画像材料，也不先持久化整轮正文再筛选。保留必要的消息身份、来源、时间与会话关联用于去重和来源查看。部分 Hook 只有状态通知，仍需复用支持的会话读取器定位用户消息；来源无法取得或无法区分真实用户输入时，应说明缺失，不能把系统注入、工具返回或模型摘要当作用户输入。

采集与形成记忆分开：建议从用户输入中提取明确的个人信息、沟通偏好、工作习惯和纠正，并保留原话及适用范围。例如“以后默认用中文”可形成偏好候选；“这个项目用 React”是项目约束，不能泛化为用户长期偏好。用户粘贴或引用的他人文字不直接视为本人观点；“可以”“按上面做”等依赖缺失上下文的输入，不凭猜测形成新画像事实。采集不等于自动确认，现有确认、纠正和遗忘能力继续保留，后续是否调整自动确认策略另行讨论。

自动接入以所有已识别的 Agent 终端为目标，不仅限于原先已装 Hook 的终端。建议在开启时检查并补齐接入，功能开启期间新识别的终端也自动纳入；复用已有 Janus Hook，安装幂等并保留用户原有 Hook 和配置。运行中的终端如需下次启动才能生效，应显示待生效，不擅自重启用户任务。Janus 内置对话使用现有消息入口接入同一条个人输入处理路径，无需额外安装外部终端 Hook。

“已识别”不等于“采集已接通”。现有[终端 Hook 适配](../terminal/terminal-hook-adapters.md)说明不同引擎依赖各自事件契约，DSH 当前没有可安装的 Hook 接口。后续实现应自动检测接入与用户消息获取能力，如实显示已接通、待生效、失败或待适配；不支持的已识别终端仍属于覆盖缺口，不能静默排除或虚报完成。复检时机、引擎适配方案和界面细节待实现前确定。

关闭个人画像仍沿用现有个人域停止采集、候选处理与召回的边界，并保留已有数据。建议只停用个人输入采集订阅及写入，保留终端状态等其他功能需要的共享 Hook；不能整套卸载共享 Hook。现有“自动积累对话”等子设置与开启即采集的新行为如何兼容、重新开启时如何处理历史输入，仍待设计。

只关注用户输入会减少对执行行为的推断，也无法仅凭“可以”还原被接受的具体方案；这是收缩材料范围的代价。

工程功能退出时保留个人输入采集所需的 Hook、来源识别和可靠写入能力，替换依赖工程全量证据的习惯推断路径。具体复用边界、提取节奏、原始输入保留期及存量数据处理仍待设计；本轮不删除 Hook、历史记录或修改个人开关。

## 工作台与审核建议

建议原知识库工作台收敛为个人画像与记忆管理，复用当前有效能力，优先支持查看已知资料与偏好、管理记忆、查看待确认项和来源、纠正、拒绝与遗忘。页签和名称由用户体验确定，不沿用工程条目或 Wiki 的概念解释个人信息。

个人审核处理记忆确认和纠正；蓝图审核处理项目 Note 的依据、条件和一致性。若共享右侧入口，分别维护筛选、计数与动作，工程审核不可用时个人审核仍能独立使用。个人确认不受项目 Note 模型评分控制。

原知识库设置区域由蓝图承接；个人设置继续表达个人采集、对话使用和保留策略。具体设置入口待设计，不能只迁移标签而丢失独立开关及已有用户配置。

## 当前维护与后续排期

当前随蓝图 B1 建立个人能力回归基线，在 B3–B4 进行个人模块剥离、共享依赖保留和必要兼容维护。原工作台或设置因工程入口退出必须调整时，保留个人访问路径和现有操作即可；不以完整重做个人工作台为本轮交付目标。

个人画像的功能扩展与界面细化移出当前 B0–B6 主线，恢复讨论后再单独排期。工程退出前仍需验证现有个人能力独立可用，以及确认、纠正、遗忘、来源查询和对话使用的效果；保留能力回归不能只检查页面存在。

## Open questions

交付计划 Q4 暂缓细化：已确认的采集来源与自动接入方向保留，终端能力缺口、提取节奏、记忆确认、原始输入保留期、旧设置兼容及重开历史、工作台页面和进一步重构深度在后续个人画像讨论中继续。Q6 已确认删除旧工程资产、由主 Agent 负责判断并持续维护共享能力，当前仅落实模块拆分、必要兼容与回归边界；本轮已落实必要拆分和个人兼容，未改变用户个人开关或进行新增自动接入；完整产品扩展仍后置。

## 本轮保留实现

个人工作台已由 PersonalMemoryWorkbench 承接现有卡片、搜索、资料与审核；旧工程分区和工程模型部署入口移除。既有 inferEngineeringHabits 为明确 opt-in 门禁，保留可归因用户消息作为习惯来源；CaptureInbox 在持久化和重放前排除助手/工具/状态正文，不继续旧工程知识采集。没有实现本篇规划的全终端自动接入或修改既有个人会话的近期记录策略。

个人候选保持显式确认，来源失败或替代对象变化会取消勾选；确认、纠正、遗忘、来源撤销及召回回归通过。工程资产迁移保留个人、原始观察、审计、凭据和模型资源，具体去留见[模块入口](module.md)。
