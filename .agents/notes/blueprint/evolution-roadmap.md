# 蓝图融合与 Note MCP：MVP 及完整版本实施计划

## Intent

当前主线是蓝图开发与优化。用户已授权按 MVP 组织首批交付，再排后续完整版本；本篇收口顺序、依赖和验收出口。旧工程知识库专用资产删除清理，共享能力由主 Agent 判断、剥离并持续维护；个人画像仅做必要解耦和兼容，不扩展产品机制。已开始建议管理、内容审核与桌面接线，功能完成以各阶段实际验收为准。

## 已确认的最新交付规则

独立关系图谱已由用户取消并移除，不再列入实施或验收范围。模块浏览、原文预览、既有关系详情与建议机制继续保留，范围见[导航模块](navigation/module.md)。

自动审核静默、后台化，不弹通知、不发声音；在蓝图顶部工具栏右侧安排紧凑活动区，显示当前阶段、对象或进度与当前错误，具体尺寸随实现完善。节点提示灯仍只表示待处理建议，不增加一套运行灯色。

Agent 在处理相关模块前和任务收尾时读取相关建议。调用约定随 MCP 工具说明与指南提供，沿用已有工作流；服务不主动唤醒会话，也不擅自重写用户的工作流文件。

用量管理只预留扩展，统计界面与预算策略后续设计；当前不设置费用、次数或 Token 用量上限。仅复用已有提供方实际返回的用量/耗时能力，不为完成 MVP 新建统计系统。

建议与 Note 的对应关系、变化联动、版本和清理由[建议管理模块](maintenance/suggestions/module.md)集中设计维护，UI 与 MCP 共用机制；目标 Note 删除后自动清理其建议，不要求人工或 Agent 再确认。不提供“复制给 Agent”功能，反馈文件导出与本地投影不列入当前交付。

不保留建议历史：已处理、不采纳或有效复核确认消除的条目清理，被完整替代的旧报告不归档；只保留当前结果、待处理建议和必要运行检查点。新审核仍可能再次提出同类问题，不建立长期拒绝记录或历史恢复功能。原始 Note、Git 历史和开发验收证据不在本项删除范围。

设置同页分为审核模型、自动审核、MCP 接入三个区域，修改即持久化并生效，无保存/应用控件。本地模型部署隐藏并暂缓。未交付的自动审核或外部导入功能不提前显示可用按钮，随对应阶段完成接入同一设置结构。

## 排期原则与当前进度

按单一主执行者串行推进，保留 M1–M3 的 MVP 与 F1–F3 的完整版本边界。M1、M2 各拆成两个可验证步骤，实际顺序为 M1.1 → M1.2 → M2.1 → M2.2 → M3 → F1 → F2 → F3。依赖、运行条件及拆分前 60 项回归见[实施基线](implementation-baseline.md)。M1–M3、F1 和 F2 的主要实现已接通；整组 702 项回归通过，真实 Gemini 生成和实际客户端调用已有证据。JEV 对比、Pi 扩展、Codex 宿主写入以及安装包升级仍未通过，不能标记完整版本完成。具体范围和证据见[实施基线](implementation-baseline.md)。此前就近暂停检查点后，已按用户授权补充设置细节、MCP 说明和建议机制修复；独立关系图谱随后取消并移除。桌面端到端夹具选择超时尚未完成修复，M2.2/M3 的完整桌面验收未签收，不以局部回归标记 MVP 或完整版本已发布。

先验证共享边界，再交付可运行的建议机制，然后接模型和界面。多进程一致性是建议存储的基础验收，在 M1.2 完成；配置更新、冲突与撤销随 F1 首批导入交付。模型质量、删除清理、状态文字及失败恢复各自在所属阶段验证，F3 负责后续终端和版本整合，不承接前面尚未完成的基础能力。

旧工程知识库按消费者逐步拆分：M1.1 建立去留清单和回归基线；M1.2–M2.2 在新能力接入时迁出必要共享依赖、清理已无消费者的局部代码；M3 完成工程专用入口、后台任务和生成资产退出。先确认替代消费者和数据归属，再删除；不因提前整理就移除仍在使用的能力，也不保留重复的新旧建议状态机。

每步结束保留必要实现与验证证据，更新所属模块事实。常规字段、缓存、重试间隔和布局由主 Agent 收口；只有实测证明需要改变已确认行为或范围时才提出取舍。外部环境或凭据缺失可先完成不依赖它的代码和替身验证，但实际调用/质量验收保持未完成，不据此提前发布。

## 工期与检查点

表中的工作量表示相对复杂度，不是天数承诺。本轮已实施主要代码与受控回归，剩余工作由兼容性与发布验收缺口决定，不给尚未具备环境的项目编造日历工期。每个步骤以阶段出口结束，避免将大阶段累积到版本末才发现基础问题。

| 检查点 | 可以确认什么 | 下一步 |
| --- | --- | --- |
| M1.1 结束 | 共享依赖、数据归属、真实验证条件及工期估算依据 | 实现建议内核 |
| M1.2 结束 | 建议生命周期和多进程存储可靠 | 接取证与模型审核 |
| M2.1 结束 | 模型输出及 JEV 核验的实际质量、失败边界可评估 | 接桌面完整路径 |
| M2.2 结束 | 用户可完成手动审核与维护反馈闭环 | 完成旧工程退出 |

| F1 / F2 / F3 结束 | 分别确认首批终端、Git 自动化、完整版本覆盖 | 保留每次验收结果，后续只补新增能力及相关回归 |

## 可独立交付的成果

- MVP（M1.1–M3）：统一建议管理、手动审核、可选 JEV、原生反馈闭环、即时设置和旧工程资产退出；个人仅必要解耦与回归。
- 外部接入（F1）：独立 Note MCP、首批三终端全局导入及完整配置维护，桌面关闭仍可使用。
- 完整版本（F2–F3）：Git 自动审核、静默活动显示、后续三终端与发布验证。
- 暂缓：个人画像扩展、本地部署、用量管理产品设计、压缩合并等特殊补检。不设置当前用量上限；不提供“复制给 Agent”，文件导出及本地反馈投影不进入交付。

旧 B 编号仅保留职责映射，不能再解释为执行顺序：B0 对应范围收口，B1 对应 M1 及 M2.1 样例，B2 对应 M2，B3/B4 分布在 M1–M3，B5 对应 F1/F3，B6 对应 F2。专题中的 M1、M2 分别包括其两个子步骤。

## 后续实施的验证重点

MVP 需要结构检查、类型/构建和相关单元/集成验证，并以真实模块材料验证审核链路。重点区分尚未实施的需求、代码偏离需求与文档过时；来源/建议版本一致，失败不伪造通过，MCP 清理不改正文或发起新审核。目标删除自动清理、改名/恢复/暂时不可用区分及迟到结果防复活，按建议管理模块的联动矩阵验收。清理后的建议不得在 UI、MCP 或归档文件中保留为历史；当前运行修订号与检查点不能演变成隐蔽历史库。

界面验证覆盖准确状态文字、折叠阅读、原文定位、部分处理/全部清理、设置立即生效、失败就地显示及无保存按钮。F2 增加无通知/无声音、活动区当前阶段和进度可见，以及等待、失败、恢复不增加节点运行灯的验证。

独立 MCP 验证首批终端实际调用、无桌面/无 WorkflowX、多个工作区和分支、配置重复导入与更新、当前报告过时及不存在时的真实结果。仅服务握手或配置写入不能替代客户端调用验证。

Git 验证包括既定初始基准和计数口径、代码-only 提交、无 Note 差异、格式/时间变化不滤掉、可识别普通合并的内部发现、通知与轮询去重、文本冲突、语义冲突和部分失败恢复。压缩合并、历史改写等特殊来源识别与补检暂缓，不纳入 MVP 或本次完整版本验收；所有来源仍必须校验实际输入版本。

“不要历史保留”指审核建议与旧报告，不取消当前任务故障诊断、必要运行检查点、项目原始 Note、Git 历史或开发验收证据。已执行的功能验证和未通过项见实施基线；其余场景不因代码存在自动视为通过。
