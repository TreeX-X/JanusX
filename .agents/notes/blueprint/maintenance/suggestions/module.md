# 蓝图建议管理

## Responsibility

集中管理审核建议与 Note 的对应关系、当前结果、来源有效性、处理和自动清理。Note 删除后自动删除其建议是已确认要求；本模块统一维护 Note 各种变化下的建议行为，供蓝图界面、原生 MCP 与独立 MCP 复用。当前内核已接入桌面、原生工具和独立 MCP，并通过文件、双进程与独立 stdio 测试。

审核服务负责读取材料、调用生成模型和可选 JEV，Git 调度负责判断何时审核；本模块接收审核结果，负责发布与保存当前建议，不修改 Note 正文、不发起模型调用。原始 Note、身份和索引继续复用 agentX 共享能力，建议规则集中实现，不分散到界面、监听回调或各个 MCP 适配器。

## Design

建议绑定项目、工作区、分支上下文、目标 Note UUID 和实际输入版本，必要依据记录自身来源及版本。路径用于定位，不能代替 UUID；同名路径、同名分支和不同工作区不自动共享建议。Janus 持久化当前数据，桌面和独立进程通过同一契约读取、处理与校验。共享状态位于 userData/janusx/blueprint/current-suggestions.sqlite，独立进程由 JANUSX_NOTE_STATE_ROOT 指向同一目录。

内部按职责组织来源事件核对、建议状态规则、当前数据存储和对外读写接口。共享规则拥有状态变更与清理的决定权，存储负责原子提交和多进程一致性，界面与 MCP 仅作适配。无需为每个事件建立独立服务，也不新增专门的建议 MCP 产品。

定向修复的交接、Note 写入与复审调度由 review/note-repair 负责；本模块拥有当前建议及其发布校验。写入后退休旧报告并持久化 awaitingReview/hash；完整复审原子替换整篇集合。完整零项结果表示本次审核通过，失败或覆盖不足仍待复审。撤销恢复原文后重新审核，不从回执恢复建议历史。交互与执行边界见[建议定向修复](../../navigation/note-updates-and-suggestion-navigation.md#建议定向修复)。

### 修复后的整批替换

内部 Janus 根据建议调整 Note 后，宿主对实际写入的新版正文重新审核。旧建议作为修复依据保留在本次交接中，写入后退出当前有效集合。complete 结果经读取、引用、来源及票据校验后整批替换，不依赖逐条 resolvedFindings，不把遗漏的旧项拼回新报告。仍存在的问题必须按当前正文描述和引用。兼容旧调用方的 resolvedFindings 输入，但完整发布不再以其为清理门槛。

失败、材料不足或无有效响应显示复审未完成，不能伪装通过；保留已写入正文，重试审核即可。若当前正文已经消除了旧问题，应允许零修改进入有效复审，不为满足 changed 标记强迫无意义改写。JEV 仅补充数字评分，不决定建议的保留、清理或审核通过。UI 流转与左侧操作区要求归[交接专题](../../navigation/note-updates-and-suggestion-navigation.md#修复闭环与左侧界面)。

普通复审覆盖不足时保留原有待处理意见及其过时标记；授权修复已退休旧集合的，覆盖不足只发布本轮实际发现的问题并保留待复审状态。审核失败保留 awaitingReview，应用重开后仍能从 Note 或“需要重试”定位。完整当前版本报告才清除待复审；旧 Git 快照结果不能为新正文解除该状态。JEV 评分只更新匹配报告 ID、来源 hash 和 findingId 的注记，不改变建议数量或处理修订号，迟到评分不能复活已处理条目。

### Note 与建议的联动

| 情况 | 统一处理规则 |
| --- | --- |
| 新建 Note | 初始没有建议，不因创建或读取自动审核；生成仍走左侧手动或 Git 自动入口。 |
| 修改正文、元数据或已读代码/关联依据 | 将受影响的当前建议标为过时，保留待处理内容；修改不等于修复，不隐式调用模型。 |
| 同一 UUID 的改名、移动或模块归属变化 | 更新定位和归属；按实际输入变化核对有效性，不按旧路径缺失误判为删除。 |
| 确认目标 Note 已删除 | 自动清理该目标在对应工作区/分支上下文中的当前报告、建议及专属依据，刷新列表、计数和提示；无需用户标记或 Agent 回写，不留历史。删除是对象退出，不表示审核通过。 |
| 删除的是其他 Note 所引用的依据 | 清理被删 Note 自身的建议；其他目标仍存在的建议标为依据缺失或过时，不能连带删除。 |
| Note 暂时读不到、解析失败或工作区离线 | 返回来源不可用或诊断，保留当前建议；不能把一次读取失败当作确认删除。 |
| 删除后恢复，或在同路径新建 Note | 不恢复已删除建议。按当前身份重新读取，未来由正常审核入口生成；旧异步结果不能复活条目，即使恢复了同一 UUID。 |
| 类型或生命周期改变 | 按当前三类审核范围和生命周期重新核对适用性；历史/归档不因状态而排除。退出三类范围后清理其目标建议，不影响它作为其他目标依据时的版本检查。 |
| 切换分支或工作树 | 读取对应上下文的当前建议，不串用结果；另一活跃上下文中的同一 UUID 不因本上下文删除而被清理。 |
| 可识别的普通合并完成 | 审核服务按最终内容生成结果，本模块发布当前版本；仍存在的未处理意见可作取证参考，不合并历史报告。压缩合并等特殊来源识别暂缓。 |

删除判定以可用来源的完整扫描或已核实的变更结果为依据，并核对身份迁移。文件监听仅提示重新核对；原子保存造成的短暂缺失、未加载分支和无法访问的目录不构成删除证据。桌面退出期间由独立 MCP 在访问时核对实际来源并执行同一清理，或在桌面重开时同步；无需常驻审核服务。确认删除后的清理不依赖自动审核开关、Git 提交数或模型配置。

### 当前建议的处理与发布

读取或展开不将建议视为已处理；读取时的来源同步若确认目标删除，仍执行自动清理。用户标记已处理/不采纳，或 Agent 通过 MCP 回写时，仅清理指定条目。完整有效的新审核结果替换整篇当前集合，零项结果清理旧项。部分处理保留其余意见；失败、材料不足、漏审和无效空响应不能作为审核通过依据；合法的完整零项报告与空响应明确区分。全部清理后隐藏提示灯，无灯不表示已经审核。

仅保存当前报告、待处理建议及必要依据。被完整替代的报告、已处理/不采纳条目和目标删除后的建议不归档，不维护长期拒绝指纹或恢复入口；新的独立审核可能再次发现同类问题。项目原始 Note、Git 历史和开发验收证据保持各自职责。

发布与处理都校验目标上下文、输入版本和当前建议修订号。每次发现已读依据的 hash 变化均递增建议修订号并使旧处理请求失效，即使报告已标为过时；重复扫描同一版本不重复递增。内部只记录依赖的最近观测 hash，兼容已有记录，不向 UI/MCP 暴露该字段。删除、恢复、切换上下文及用户清理使旧任务失效，迟到结果不得覆盖或复活已清理内容。仅保存防止旧结果写回所需的当前代数、修订号和运行检查点，不借此保存已删除建议正文或处理历史。重复处理不存在的条目返回明确的当前状态，不影响后续新条目。

UI、MCP 列表、计数与详情消费同一当前状态；索引和缓存随提交失效。单个目标清理不得删除其他目标仍需的共享依据。具体锁、事务和失效实现复用共享基础，在 M1.2 完成并用两个独立进程验证；M2 接模型、界面与原生工具，F1 的独立终端接入沿用同一机制，不将基础并发正确性推迟到 F3。

## 当前实现与验证

src/main/blueprint/suggestions 按来源读取、领域规则、SQLite 存储和工作区入口组织。WorkspaceSuggestionSources 使用 agentX NoteService，核对真实 checkout、分支、原始文件 hash 和完整扫描；不另建 Note 解析器。索引暂时被其他读取者锁住时短暂重试，持续占用仍报告失败。WorkspaceSuggestions 在事务外核对来源，提交时校验状态修订，并校验模型引用确实来自原文；自动审核的提交快照引用在对应 Git 对象上核对，当前工作区差异标为过时。建议存储仅保存当前报告、未处理问题和防止迟到结果写回所需的代数；secure_delete 与短事务用于清理及独立进程一致性。构建后的桌面读入、清理与独立 MCP 握手已验证，安装包仍待验证。

普通内容变化使报告过时；两次稳定完整扫描及短暂缺失缓冲确认删除。解析失败、重复身份、来源不完整或工作区不可用不作为删除依据。发布时优先沿用当前问题 ID；模型更换 ID 时，仅在类别、规范化正文和精确引用相同的情况下合并当前重复问题。同标题但依据或解释不同仍为不同问题，不使用模糊匹配。清理后不保存指纹，新审核可产生新的问题 ID。新报告中的空结果不清理旧意见；模型须显式给出问题 ID、消除理由及当前引用，材料不足不得声明消除。消除理由只作为此次发布校验输入，不保存为处理历史。

验证命令 npx vitest run tests/unit/blueprint-suggestions.test.ts tests/unit/blueprint-suggestions-process.test.ts --maxWorkers=2，19 项通过，覆盖生命周期、实际文件、原文引用、上下文隔离、已过时报告的连续依赖变更、同内容新 ID 去重、两个独立进程部分清理和删除竞争、重开一致性。实际客户端读写和宿主限制见[实施基线](../../implementation-baseline.md)；安装包验收独立记录。

## Acceptance criteria

- [x] AC-1: 新建、修改、移动、删除、恢复、来源失效及分支切换使用统一规则，UI 与两类 MCP 不各自维护状态机。
- [x] AC-2: 确认删除目标后自动清理其建议、报告与专属派生内容；关闭自动审核或缺少模型不阻止清理，不保留建议历史。
- [x] AC-3: 改名、原子保存、解析失败和工作区不可用不误删；其他活跃上下文及引用被删来源的其他目标正确保留。
- [x] AC-4: 处理、删除、恢复和并发发布的旧请求不能复活条目；部分处理和失败不会误清理其余建议。
- [ ] AC-5: 桌面与独立 MCP 共用持久化与版本语义；读取/清理不修改 Note 或生成审核，桌面重开后状态一致。
