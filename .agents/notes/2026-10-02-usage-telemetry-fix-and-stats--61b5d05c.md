# 终端用量统计修复与全局统计

## Problem

全终端用量统计存在两处系统性缺陷，dsh 接入时仅做了最小锚定规避，未根治。来源见 [DSH 接入决策](./2026-09-30-dsh-terminal-integration--b28d07a3.md)，即提取出做全局任务的母篇。

- 模型误判：PTY 文本解析把散文当作模型声明，例如显式 `model: the behavior` 取到 `the`，宽松裸词在散文中误命中。
- 上下文误解析与不累积：`used/window` 分数无量级校验，帮助文本分数进入遥测；用量没有正确累加，窗口显示长期为零或初始值；各终端无统一聚合视图。

## Expected behavior

分两轨交付，均需独立于 dsh 合并单独验证全引擎回归。

- 轨道 A 统计修复优化：显式与宽松模型分支统一走合理性门，散文不再成为模型声明；显式上下文分数要求真实量级窗口且 `used` 受窗口约束，否则丢弃；累积合并语义保持并被回归测试锁定。
- 轨道 B 全局统计：设置中的独立用量视图跨终端类型聚合累计 token 消耗，支持今日、本周、本月筛选。两个环形图、趋势图与底部分组共同使用所选终端类型和时间范围。整体环形按终端类型占比取工具品牌色，缓存环形区分读缓存命中数与新鲜输入加缓存写入数；无缓存字段时显式标无数据，不按 0% 计。趋势图使用纯 SVG 绘制命中与输出两条曲线，支持悬停和键盘聚焦读取时间桶数值；未命中与未区分不进趋势图，前者由缓存环形承担，聚合口径中的 hits/misses/unknown/output 字段不变。时间桶按终端最近更新时间归入累计快照，不代表逐时新增消耗，图表旁明确注明此口径。底部按终端分组，以大数字显示合计与命中率，模型名称单独展示；同组多个模型不声称各自独立用量。
- 非目标：在拿到配 key 的真实会话样本前，不臆测 dsh 成功结束标记、审批与问卷面板信号、状态栏数值与上下文数值格式。

## Scope

In scope：`src/renderer/src/lib/runtime-telemetry.ts` 的检测门与累积语义回归测试、设置面板新增 `UsageStatsPanel` 及聚合数据源接线、对应单测与文档。

Out of scope：`session.v4.jsonl.zstd` 解码、pid 到会话挂载匹配、无 hook 自动绑定、dsh 成功结束与审批与数值解析在无样本时落地、dsh 模型配置投影。

## Proposal

轨道 A 只收敛判断门与回归测试，不改合并语义：显式分支与宽松分支共用单 token 加版本与分隔符 hint 门，dsh 状态栏保持友好锚定加同门；分数门要求窗口具备真实量级且 `used` 不超过窗口；合并侧保持单调累积、低置信不覆盖高置信、会话切换清零。

轨道 B 新建设置面板组件，按终端加按时间聚合展示累计用量，空状态与缺数据源保持可解释；聚合只读现有遥测与历史扫描结果，不新增终端私有协议解析。落点已定：设置独立 `usage` Tab（紧随 `llm`，与 LLM 配置同类布局：`terminalTabs` 按终端类型筛选加时间范围筛选，按类型分组展示），通用页不内嵌；右栏 sessions 与终端状态栏只保留实时遥测，不做历史归宿。

## Alternatives considered

- Do nothing：dsh 侧锚定已规避散文误判，代价是全引擎统计继续错误且无全局视图，问题会随终端增多放大。
- 随 dsh 合并一起修全引擎：改动面覆盖所有终端与设置面板，回归风险高，母篇已在 2026-09-30 明确拒绝。
- 顺手解 zstd 与 pid 挂载：无解码器且 conpty 中间层 pid 与挂载内层 pid 不一致，投入大而信号不可靠，留待有样本与解码能力后再议。
- 复用堆叠条形和通用信息卡：实现简单，但难以比较各项趋势，密集描述文字也弱化关键数字。独立样式模块与 SVG 曲线让筛选后的数据层级清晰，代价是维护坐标、曲线和键盘聚焦；不引入图表依赖。若需要真实消耗速率，必须先补充历史增量采样，不能只改变图表形状。

## Acceptance criteria

- [x] AC-1: 模型声明不再误判散文，显式与宽松分支均过合理性门，真实模型 id 不受影响。
- [x] AC-2: 显式上下文分数具备量级门与上下界约束，散文分数被丢弃，无锚定单轮用量保持不进入窗口。
- [x] AC-3: 累积合并语义被单测锁定，单调累积与置信排序与会话切换行为有回归覆盖。
- [x] AC-4: 设置面板全局视图按终端聚合历史累计用量，支持今日与本周与本月筛选，空与缺数据可解释。
- [ ] AC-5: dsh 成功结束与审批与数值格式在无真实样本时不落地，需求保持显式未做。
- [x] AC-6: 两个环形、命中与输出两线趋势和终端模型分组随终端类型与时间范围一起切换；空状态不显示缓存命中率为零。`tests/e2e/usage-stats.spec.ts` 覆盖筛选、时间范围、键盘读数和窄窗口，`tests/unit/usage-stats.test.ts` 覆盖聚合口径。

## Risks

全引擎回归面广，需覆盖各终端既有单测与设置面板 i18n；聚合查询需避免阻塞渲染，大时间范围走按需计算；最大诱惑是臆测 dsh 私有格式，必须以真实样本为准。
