# Android 异网信令

新配置默认异网并使用 `wss://janusx-signal-entry.pages.dev/signal`。电脑直连和经代理分别通过八项 HTTPS/WSS 信令检查，手机新入口和真实异网 UDP 仍待验证。真机对原 workers.dev 入口 TLS 超时，而百度 TLS 成功，故增加 Pages 入口；尚未确定手机 VPN/DNS 阻塞的具体原因。旧配置中明确选择的 LAN/自建服务会保留，旧官方完整地址、空地址或临时 Quick Tunnel 地址迁移到新入口。桌面与后续 Android 构建共享默认 JSON，现有 Android 0.1.10 重新扫码即可使用新地址，无需安装新包。局域网模式生成的 `ws://192.168.x.x:43821/signal` 仍只能用于可互访网络，STUN 不会把它变成公网服务。

异网使用现有 SDP/ICE 信令服务。电脑和手机都连接同一个公网 `wss://` 地址；信令转发经过 HMAC 认证的 SDP 和非 relay 的 UDP 候选，不接收配对密钥、授权 token、终端内容或命令。终端仍走双方直接建立的 UDP DataChannel，不使用 TURN。公开信令可观察连接 IP 与 SDP/ICE 元数据。

## 长期入口与用户体验

Quick Tunnel 的随机地址仅验证公网信令可达，依赖当前电脑和两个后台进程，重建地址会变化，不是长期服务。仅把随机地址改成固定域名也不解决进程退出、电脑休眠或网络故障；需要持续运行、自动重启、TLS 续期和健康监控。

当前默认入口部署在 Cloudflare Pages，通过内部服务绑定连接 Workers + SQLite Durable Object，使用平台域名和免费额度，不依赖开发电脑或隧道进程。普通用户开启、扫码和批准，自建地址仍可填写。维护方仍负责账号、配额与可用性；旧 workers.dev 入口本机无代理访问曾超时，新 Pages 入口本机直连通过，但不代表手机或所有国内网络可用。不把临时隧道当作默认服务，也不声明生产可靠性已验收。

自用过渡可以使用自有域名的 Cloudflare Named Tunnel 加开机启动，地址能保持固定，但仍依赖运行信令的电脑和 cloudflared；需要自己的 Cloudflare 账户、域名和持久隧道配置，不能把 Quick Tunnel 的地址固定下来就视为完成。面向多用户建议让信令独立部署，避免开发电脑成为公共入口的可用性依赖。

公网信令负责让两端交换地址和连接协商，业务仍直接 UDP P2P。采用纯 UDP 业务传输并不消除发现对端的需求；无公网信令时，需用户另行双向交换 SDP/候选，动态重试与多候选同步也会增加操作。长期服务解决的是入口和配置体验，不会自动修复运营商 UDP 路径限制。

## 构建与部署

免费 Workers + SQLite Durable Object 版本见 [Cloudflare 部署](./cloudflare/README.md)，兼容现有桌面和 Android SDP/UDP ICE 协议。以下保留自建 Node 方式。

在已安装仓库依赖的开发电脑运行：

```powershell
npm run remote:signal:build
```

将 `artifacts/remote-signal/server.mjs` 复制到有公网入口的服务器，使用 Node.js 22+ 运行，无需安装 npm 依赖：

```sh
LISTEN=127.0.0.1 PORT=43821 node server.mjs
```

使用进程管理器保持运行，配置崩溃后自动重启和开机启动。将自己的域名解析到服务器，并用有效的受信任 TLS 证书反向代理 WebSocket。例如 Caddy 配置（替换示例域名）：

```caddyfile
signal.example.com {
    reverse_proxy 127.0.0.1:43821
}
```

服务器对外开放 HTTPS 443；43821 保持仅回环监听。反向代理需支持 WebSocket Upgrade，保留 `/signal` 路径；健康检查可请求 HTTPS 根路径，返回 `JanusX signaling`。信令含心跳、加入超时、消息大小与连接限制；它是实验连接服务，未实现账号、长期设备身份或集群房间共享。多实例必须保证同一邀请双方进入同一实例。

部署后应从外网验证 HTTPS、双端 WSS 入房、SDP/候选转发和心跳，持续监控可用性及证书有效期；重启进程管理器和服务器后复验同一域名可连接。确认长期入口后再预置应用默认地址。只配置 DNS 或通过一次健康检查不代表具备长期可靠性。

## 两端配置与排障

更新桌面和 Android 0.1.6，开启创新功能中的远程开关。在手机远程面板选择“异网连接”，填写 `wss://自己的域名/signal`，按网络需要设置可达的 `stun:` 地址，然后重新生成二维码。手机扫码后仍需在电脑批准。地址配置会保存在当前桌面 profile，二维码及密钥不会保存到该配置。

同一局域网选择手机可访问的物理网卡。桌面排除 APIPA 和回环地址，并将常见虚拟网卡排在后面；这不等于自动检测出所有机器的默认路由，多网卡时应手动确认。调试 Android 允许局域网 `ws://`，正式版要求 `wss://`。

手机“详情”按阶段显示连接结果：

| 阶段 | 检查方向 |
| --- | --- |
| SIGNAL failed / 未连通信令 | 先检查二维码地址是否公网可达、DNS、TLS、443 和反向代理路径；此时尚未进行 UDP 打洞 |
| SIGNAL joined，未收到 SDP | 检查电脑是否仍开启远程、双方信令地址/邀请是否一致；重新生成二维码 |
| SDP 已验证，UDP 等待重试 / 超时 | 查看当前 round、本地 UDP/srflx/IPv6、remote 收到、applied/rejected，以及 pairs/checks/responses/succeeded；区分候选未应用和已检查但无应答，不能单凭 remote 数量归因 |
| DATA OPEN / 等待批准 | UDP 已建立，需在电脑面板批准手机 |

没有 srflx 不足以单独断言失败原因；有映射也不证明双方可达。无中继不能保证对称 NAT、蜂窝运营商过滤或禁止 UDP 的网络连接成功。不要把信令代理扩展为终端业务代理来绕过当前需求约束。

0.1.6 在未打开数据通道时最多重新协商三轮，每轮 20 秒；手机总等待 75 秒，保留建连阶段失败后的信令。新轮次先发送签名 SDP，再发送候选，并按 ICE ufrag 丢弃旧轮次消息和回调。应用候选失败会计数并继续其他候选；三轮均失败时保留诊断，避免无限重试。旧 Android 会在首轮 ICE FAILED 时断开，因此需同时更新两端。持续收集和保留可用 IPv6/多网卡候选不等于所有网络都具备这些路径。

Android 主动断开会立即取消旧信令 socket；新连接尚未入房时遇到 1008 拒绝，最多间隔 500ms 重试三次，容忍旧连接延迟释放房间。入房后的协议拒绝仍结束连接，信令不允许新连接任意挤掉同角色在线设备。

本机自动化可设置 `JANUSX_SMOKE_RETRY=1` 后运行 `node scripts/android-lab/desktop-smoke.mjs`：只在测试隐藏窗口拦截第一轮候选，验证 Android 保留信令并在第二轮真实 UDP 配对；重连时临时占用 client 角色，验证 Android 等待释放后入房，并再次快速重连同一终端。故障注入只验证重试机制，不模拟真实运营商 NAT。

本地自动化与模拟器仅验证本机链路。真正异网需要真实手机切换蜂窝网络，连接另一个网络的电脑，保留双方阶段日志和选中 UDP 路径，并验证 Claude 启动、交互、断线恢复；不得用本机 STUN 探测或模拟器通过替代这项验收。
