# Android 异网信令

电脑默认生成的 `ws://192.168.x.x:43821/signal` 只能供可互访的局域网使用。手机切换蜂窝网络后通常无法访问它，连接会在 WebRTC 协商之前失败。STUN 仅帮助获得 UDP 映射，不会把本地信令变成公网服务。

异网使用现有 SDP/ICE 信令服务。电脑和手机都连接同一个公网 `wss://` 地址；信令转发经过 HMAC 认证的 SDP 和非 relay 的 UDP 候选，不接收配对密钥、授权 token、终端内容或命令。终端仍走双方直接建立的 UDP DataChannel，不使用 TURN。公开信令可观察连接 IP 与 SDP/ICE 元数据。

## 构建与部署

在已安装仓库依赖的开发电脑运行：

```powershell
npm run remote:signal:build
```

将 `artifacts/remote-signal/server.mjs` 复制到有公网入口的服务器，使用 Node.js 22+ 运行，无需安装 npm 依赖：

```sh
LISTEN=127.0.0.1 PORT=43821 node server.mjs
```

使用进程管理器保持运行。将自己的域名解析到服务器，并用有效的受信任 TLS 证书反向代理 WebSocket。例如 Caddy 配置（替换示例域名）：

```caddyfile
signal.example.com {
    reverse_proxy 127.0.0.1:43821
}
```

服务器对外开放 HTTPS 443；43821 保持仅回环监听。反向代理需支持 WebSocket Upgrade，保留 `/signal` 路径；健康检查可请求 HTTPS 根路径，返回 `JanusX signaling`。信令含心跳、加入超时、消息大小与连接限制；它是实验连接服务，未实现账号、长期设备身份或集群房间共享。多实例必须保证同一邀请双方进入同一实例。

## 两端配置与排障

更新桌面和 Android 0.1.5，开启创新功能中的远程开关。在手机远程面板选择“异网连接”，填写 `wss://自己的域名/signal`，按网络需要设置可达的 `stun:` 地址，然后重新生成二维码。手机扫码后仍需在电脑批准。地址配置会保存在当前桌面 profile，二维码及密钥不会保存到该配置。

同一局域网选择手机可访问的物理网卡。桌面排除 APIPA 和回环地址，并将常见虚拟网卡排在后面；这不等于自动检测出所有机器的默认路由，多网卡时应手动确认。调试 Android 允许局域网 `ws://`，正式版要求 `wss://`。

手机“详情”按阶段显示连接结果：

| 阶段 | 检查方向 |
| --- | --- |
| SIGNAL failed / 未连通信令 | 先检查二维码地址是否公网可达、DNS、TLS、443 和反向代理路径；此时尚未进行 UDP 打洞 |
| SIGNAL joined，未收到 SDP | 检查电脑是否仍开启远程、双方信令地址/邀请是否一致；重新生成二维码 |
| SDP 已验证，ICE FAILED / 超时 | 查看两端本地 UDP、srflx 映射及对端候选数量，检查 STUN 可达性、UDP、防火墙、NAT；可更换网络复测 |
| DATA OPEN / 等待批准 | UDP 已建立，需在电脑面板批准手机 |

没有 srflx 不足以单独断言失败原因；有映射也不证明双方可达。无中继不能保证对称 NAT、蜂窝运营商过滤或禁止 UDP 的网络连接成功。不要把信令代理扩展为终端业务代理来绕过当前需求约束。

本地自动化与模拟器仅验证本机链路。真正异网需要真实手机切换蜂窝网络，连接另一个网络的电脑，保留双方阶段日志和选中 UDP 路径，并验证 Claude 启动、交互、断线恢复；不得用本机 STUN 探测或模拟器通过替代这项验收。
